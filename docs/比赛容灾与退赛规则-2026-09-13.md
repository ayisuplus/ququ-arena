# 比赛容灾与退赛规则

新比赛按模型独立累计失败，达到 3 次即弃权。默认每题最多重试 2 次，失败次数跨题累计，成功作答不清零；新开一场重新计数。

每道题从取得并发位置、实际开始调用时计时，60 秒内必须完成最终答案。时限覆盖首字等待、公开推理、答案流、重试和 Retry-After 等待，不因新增思考或重试刷新。排队不占时限。超时立即退赛，取消该模型在途调用，跳过剩余题目；全员退出时提前结束。

- 空答案记为调用失败。明确不可恢复的 HTTP 错误（如 401/403）直接退出，避免继续消耗调用。
- OpenRouter 日免费额度耗尽时隔离共享该额度的免费选手，其他接口继续比赛。
- 裁判使用独立的 60 秒时限；失败保留模型最终答案，标记裁判弃权，不累计选手失败。
- 手动终止、超时和退赛可释放等待中的并发位置，即使适配器没有响应取消；迟到增量与最终结果不再写回。
- 流式协议结束或解析失败后取消响应体读取，避免悬挂连接。
- 退赛原因进入 SSE、完整状态快照、时间轴、战绩 JSON、战报、解说和结算，断线恢复及历史回放保持一致。

退赛前有效答案保留，错误和未作答不伪记为有效零分。退赛选手无本场名次，也不作为效率比较基线。仍在赛的选手完成全部题目后按现有综合规则比较；只剩一位且完成全部题目时胜出。生涯 Elo 保留有效逐题比较，不给退赛选手颁发冠军、领奖台或新成就。旧战绩不追溯重判。

## 验证

- `npm test`：318 / 318 通过，包含累计失败、持续思考超时、长退避、队列计时、迟到回调、无响应取消、空答案、401、共享额度隔离、裁判独立超时与退赛结算。
- `node scripts/verify-resilience.mjs`：三个本机 HTTP 接口，一路连续 503，一路持续发送思考但永不交答案，一路正常；使用生产 60 秒时限，无外部 API 调用。连续故障调用恰好 3 次；超时选手调用 1 次，实测从上游收到请求至退赛 59,995 ms，HTTP 流已关闭；正常选手完成 2 题并获胜。保存记录、时间轴、重连快照和回放均通过；回放没有新增模型请求。
- `node scripts/verify-spectator.mjs`：1080p/1440p 的 2/4/8/16 窗口及原有全屏交互通过；退赛提示、后续题目保持退赛、正常选手继续输出、刷新恢复通过。

证据：[本机 HTTP 验证](validation/resilience/checks.json)、[浏览器验收](validation/spectator/checks.json)、[退赛界面](validation/spectator/resilience-1080p.png)。所有故障使用独立合成数据；正式生涯数据未修改。
