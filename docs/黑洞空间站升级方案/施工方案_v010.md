## 1. 这次真正要改变什么

目前的问题不宜只归结为“米数太小”。现有 240 × 240 m 核心已经不小，但大部分空间仍围绕赛场、连桥和功能房组织，扩大同类走廊仍会像一个更大的场馆。新的体验重点是：访客从东北港区抵达，能在外围选择方向、进入街区、遇见住在核心的大模型、发现目的地，再决定什么时候去中心看比赛。

用户这次草图是新世界总图的最高依据：中央方框为现有区域，圆形轮廓为外围扩建边界，四条径向连接构成十字分区。图中没有规定四区主题、最终米数和建筑样式，下文对这些事项给出建议，不把建议当作已确认设计。

| 已明确的方向 | 本版建议、仍待灰盒验证 |
| --- | --- |
| 第一人称漫游是主体验 | 舒适步速先试 3.5 m/s，快走／跑动先试 6 m/s |
| 现有建筑改造为大模型房间与中央擂台体系 | 核心住房分成数个小院与短廊，公共职能迁往外围；玩家没有专属房间 |
| 现有区域外扩，十字分成四区 | 西北科研、东北港区、东南公共生活、西南生态花园 |
| 整体继续建立在黑洞之上 | 外围按 720 m 直径试作平面；黑洞位置和视觉尺度单独验证 |
| 后续仍可扩建 | 核心房间用稳定 ID 关联模型；预留可定位的空模块和封闭扩建边界，不把六间写成容量上限 |

## 3. 世界总图：中央核心＋四区＋外环

北向朝上，Unity 的 X 为东西、Z 为南北、Y 为高度。以下是关系示意，不是施工比例图。

```text
                         北向主轴
                 ╭─────────┬─────────╮
                 │ 西北    │    东北 │
                 │ 科研观测│抵达港区 │
                 │     ┌───┴───┐     │
          西向主轴├─────┤现有核心├─────┤东向主轴
                 │     │模型家·擂台│    │
                 │     └───┬───┘     │
                 │ 西南    │    东南 │
                 │ 生态花园│公共生活 │
                 ╰─────────┴─────────╯
                         南向主轴
                  圆周为连续外围观景环路
                    黑洞位于整体结构下方
```

十字线应当是宽敞、能看出目的地的公共道路，兼作分区边界。道路两侧有开口、广场与街区入口；不用四面高墙把世界切成互不相通的盒子。四条道路到达核心边缘后接入公共回廊，**不穿过中央空洞，也不穿越私人卧室和选手专用路线**。

世界包含三个尺度：核心公共回廊负责探访模型住处和观赛，四条径向主路负责快速辨向，外围环路负责绕行与跨区。每个区内部另有弯折的小路、可进入空间与局部高差。玩家可以“港区→街区→邻区→核心→另一个街区”闭环游逛，不必每逛完一区都原路返回。

圆形是总轮廓，区内形态可以不对称。四区的身份通过建筑轮廓、光线、材质、声音和活动辨认，而非只换四种灯光颜色。

## 4. 中央核心如何改造

中央保留环形擂台、坠落井、观众席、裁判／播报与赛事必要设备；外围既有建筑和可改造空间转为角色住处、居住通道与小型共享起居空间。旧方框、菱形、环台成为“老核心”的内部识别骨架，不再限定整个世界。

| 现有空间／能力 | 新职责与迁移去向 |
| --- | --- |
| 旧玩家舱、角色样板房、既有建筑外壳 | 旧玩家舱分配给 DeepSeek；ChatGPT、Claude 保留原住房；西侧旧观测展厅安排 Gemini、GLM、Kimi，按稳定模型 ID 关联房间 |
| 东侧居民客厅与咖啡设施 | 客厅缩为住区共享起居；作为公共目的地的咖啡厅和完整服务迁入东南区 |
| 西侧科研庭院、研究终端 | 旧空间转为住房／共享书房；公共科研、档案与观测职能迁入西北区 |
| 南侧温室及照料交互 | 种植与公共花园迁入西南区；旧位置转为住区配套或核心出入口 |
| 北侧抵达厅、气闸、货运与停靠舱 | 归入北轴与东北港区的迁移范围；完整港口向外环发展，旧接口作为过渡入口 |
| 上层／下层环路与四角节点 | 可复用作核心住宅公共廊、观赛平台及设备路线；向新区接出明确入口 |
| 环台、双电梯、两块载人显隐平台、中央井 | 保持赛事结构和动态净空，外围建筑不占用其运动与坠落包络 |

“现有建筑改造为住处”不要求把机械井、承重设备和看台也塞进卧室。必要赛事设施继续服务擂台，其余独立公共目的地移到外区，避免世界功能仍全部挤在中心。

房间建议先按 30–45 m² 的人尺度模块试作，家具和门窗可以复用，布局、收藏和工作台表达不同角色。不要把大块三角地面切成一排无尽的房门；分成几组房间、短廊、内院和共享客厅。当前六个模型均分配住房；这只是现有名单，不是未来房间总数上限。

模型住处应有私密感：赛事入口与住宅入口分开，门厅和折线走廊缓冲赛场噪声。每一间卧室都不是公共道路的必经之处。比赛仍是整个世界共同的事件，玩家远离核心时能收到广播或看公共转播屏，自主决定是否回场。

## 5. 四个外围街区

### 西北：科研观测区——安静、深邃、逐步接近黑洞

从展廊进入观测庭院，再经工作室到达略低的观测平台。远处看得到大型仪器和挑出的观测窗，走近后能进入其中。研究档案、公开赛题与已结算答卷继续读取现有后端。

首批做一个可步入展廊、一个研究台和一个黑洞观景终点；小路从仪器背后接回外环。设计重点是看景与发现信息，不在首版新增复杂科研模拟系统。

### 东北：抵达港区——高大、忙碌、具有空间站外部联系

复用北侧接驳基础，向外围形成抵达广场、停靠大厅、货运工作面与上层观景廊。玩家能从高处看到停靠舱和搬运路线，再走到下面的维修点；客流与货运路线有可辨认的分隔。

首批复用双门气闸、停靠舱与现有检修工单。飞船承担停靠景观和有限内部访问，不把可驾驶飞船、星际旅行加入本轮目标。港口入口可落在北轴，主要体量位于东北象限，避免重新造一条孤立的北向长尾。

### 东南：公共生活区——最容易让玩家愿意停留

布置一条带转折的生活街、观景咖啡厅、小广场和公共活动空间。角色从核心住处出门，在这里喝咖啡、交谈、看赛事转播；玩家既可穿街去港区，也能沿南侧进入花园。

东南生活街已有咖啡、座位和局部居民日程灰盒；目前只有 ChatGPT 会走到咖啡厅并站立停留，尚未实现居民入座动作。完整的“模型从房间出门→到店→坐下→返回住房”仍是后续验收目标；访客可以在途中相遇、停留并换路继续漫游。初版店铺应有明确用途，不做一排无法进入的招牌，也不为撑满街道新增经济系统。

### 西南：生态花园区——开阔、有层次、给世界留呼吸空间

采用覆有透明围护的分层花园：主路较直接，小路绕过植物、水景与休息台，温室工作间隐藏在稍低的一层。与公共生活区相接的一侧热闹，接近科研区的一侧安静。

首批复用植物照料，增加可走的花园环路与一个停留点。水景先承担景观与声音，不承诺流体模拟。生态区应让玩家离开建筑廊道，仍保持可读的出口与回程方向。

每区首个有效版本至少具备：**一个远处可辨认且可到达的地标、两个用途不同的停留点、一条区内绕行路线、通往邻区的公共连接。** 不把四个已有小房间重新命名就算四区完成。

## 6. 尺度建议：先试 720 m 外径

按现有核心 240 m 边长，建议从 **720 m 外径**开始灰盒：核心宽约为全图直径的三分之一，接近用户草图的视觉关系。尺寸可在真人走图后调整，当前不冻结。

| 项目 | 候选值与含义 |
| --- | --- |
| 全站圆形外包络 | 直径 720 m，投影面积约 0.407 km² |
| 原核心包络 | 240 × 240 m，约占总投影 14%；含空洞，不等于楼面面积 |
| 外围扩展包络 | 约 0.350 km²；含建筑、空隙、结构与景观，不能宣称全部可走 |
| 四条径向主路 | 从核心边到圆周约 240 m；主路净宽先试 8–12 m，以门厅、树池和设施形成步行尺度 |
| 外围环路 | 中线先试半径 330 m，完整一圈约 2.07 km；四区均可进出 |
| 首批垂直内容 | 主层完整连通，局部上台／下行；不一次建设四区的整套多层楼面 |

用候选步速 3.5 m/s 计算，核心边到外边约 69 秒，外环一圈约 9.9 分钟，均是无停留的几何估算，不是游玩实测。现有 6／9 m/s 控制器数值过快，不能直接拿旧探针时间证明新区逛起来舒服。

实际路线需要折转、进门和停留。设计目标是访客离开东北抵达点后尽快遇见第一个生活点，主游逛路线每 20–40 秒出现一个有意义的空间变化；这些变化可以是景观、交叉口、角色或可进入建筑，不要求处处弹任务。现有东北抵达点到 DeepSeek 房间的碰撞探针路线约 589 m，暴露出途中内容密度仍不足，不能用“已连通”代替此目标。

若灰盒出现长时间空走，优先收紧功能点间距、增加横向连通和层次，再判断是否缩小外径。不要靠继续抬高移动速度补救。新增面积也不应铺成一张完整圆形大地板：用街区基座、庭院、可理解的结构空隙和观景开口组合出圆形轮廓。

## 7. 第一人称与黑洞如何共同成立

默认从东北港区公共抵达点以第一人称进入，步行、抬头看建筑、低头看平台边缘、靠近窗户看黑洞，都按眼高验证。旧玩家舱现在是 DeepSeek 住所，不作为玩家出生点。摄影自由镜头和比赛特写保留为主动进入的辅助模式，结束后返回原位置和原视角；不能让开赛广播突然夺走漫游控制权。

门、扶手、座椅、楼梯、桌面、灯具和导览的尺寸，以约 1.63 m 当前眼高和真人键鼠为起点重新核查。首批交互复用现有操作，增加清楚的靠近提示；无强制镜头摇晃，用视距、鼠标控制和合适通行宽度保证可读性。

全站仍位于黑洞上方，中央空洞维持贯通。外围增加后，站体本身会遮住更多黑洞，必须专门留三类真实视线：中心井口向下的震撼视角，外围边缘向下／向外的全景，科研区低层挑台的斜向近景。每区至少有一个无需切摄影机即可到达的观景点。不要承诺任意窗户都能看见黑洞。

W4G 当前黑洞渲染体中心约 `(0,-145,0)`、代理网格缩放 `(800,800,800)`，第一人称相机远裁剪 1200 m；旧 Observatory 候选仍使用 `(500,500,560)`。网格缩放只界定着色体积的可见范围，不是黑洞物理直径，也未改变 Shader 的 `_Radius=18`。扩建后仍须从五个位置核验构图：中央看台、核心出口、外围边缘、科研下层、花园步道，再调整黑洞表现、裁剪和照明；不能按地图比例机械放大。

居住、港区、公共街道与花园应有可信的压力围护。这里的“开放世界”指连续自由漫游，公共街区可位于高大的透明围护之内；外部检修挑台使用明确的科幻防护设定。围护分区施工，避免第一轮就制作覆盖全图的单一巨型玻璃穹顶。黑洞上方的稳定与人工重力沿用科幻设定。

## 9. 技术落地：迁移空间，保持状态连续并预留扩建

沿用现有工程分层与赛事接口，不在扩建阶段重写后端。

- **赛事状态独立于街区显示。** `BattleEngine` 继续负责赛果与结算，Unity 表现消费现有事件。玩家到港区、花园或卸载远处装饰时，比赛不重开、不丢结果；返回后不重复颁奖。
- **街区负责空间和本地交互。** 第一轮采用独立候选场景内的核心根节点和四区根节点，统一坐标基准与连接边界。先使用可见性、LOD 和分组管理；仅在测量显示必要时引入增量场景加载，避免先搭庞大框架。
- **角色身份与空间位置分开。** 房间和生活状态保持稳定 ID，房间重新定位不等于新建角色；居民从住处到公共区有可走路线。生活实体与赛事选手继续做唯一可见实例交接。
- **迁移要同时处理脚本与存档。** 当前居民使用显式 `Vector3[] Route`，安全位置校验依赖地板名字和北侧货运坐标；仅移动模型会留下旧路线与失效出生点。迁移时同步调整这些具体依赖，不顺手重构无关系统。[居民日程](../../QuQuArena3D/Assets/Scripts/App/StationResidentRoutine.cs)、[安全存档](../../QuQuArena3D/Assets/Scripts/App/StationWorldSave.cs)
- **旧存档有明确落点。** 保存版本与迁移映射，先在副本验证；旧安全点所在建筑改变后，回到对应房间入口或已验证的公共落点，保留咖啡、温室、工单等进度。不能把玩家载入墙内或黑洞上方。

当前 W4A 在西侧旧展厅留下一个**未分配的 7 × 6 m 房间位**，中心约 `(-90.5, 0, 55)`；向西的住宅支廊接口约 `(-96, 0, 55)`，压力外墙保持封闭。它们是场景中的定位标记，不是第七间已建成住房。新增模型时，先核对稳定模型 ID、为其分配新房和可走的共享廊，再沿接口逐段接新舱；不得占据现有公共通道、中央井、擂台机械包络或四区十字主路。新增支廊的承重、围护、疏散、性能与生活路径每段单独验收，不凭预留标记宣称无限扩建能力。

继续保留普通对局双人返航、冠军决赛撤败者板、冠军升空接杯和双侧真实入场。外围建筑、玻璃顶棚及合并网格不得侵入中央井与运动机构。

## 10. 施工顺序与验收

不估承诺工期；每一步先通过下面的门槛，再扩大投入。W0–W3 有候选灰盒与局部验证，W4A 正在落实模型住宅与新访客起点；旧表格中的完整体验门槛仍按原定义执行。

| 阶段 | 交付 | 通过什么才进入下一阶段 |
| --- | --- | --- |
| W0 总图与迁移清单 | 冻结候选核心包络、四区边界、出入口、既有设施去向与存档映射；复制候选场景 | 每个旧公共功能有去处，每个新区域有入口；保留当前可运行基线 |
| W1 第一人称全图灰盒 | 四条主轴、外环、四区基座与地标体块、核心四个公共出口 | 真人从核心连续走入四区，能不经核心跨邻区；无传送补路、无私人房必经、中央井与赛事机构仍通 |
| W2 完整生活切片 | 核心一组模型房间＋东南生活街＋连接花园的回程支路，完成近景样板与已有交互迁移 | 真实键鼠验证模型出门与返回、访客取饮与停留、换路继续漫游，验证第一人称尺寸和保存恢复；先证明值得逛 |
| W3 其余三街区 | 科研、港区、花园各一个完整目的地及邻区连接，迁入已有交互 | 四区各有地标、两个不同停留点与绕行路径；20 分钟游玩无需原地绕圈凑时长 |
| W4A 模型住宅候选 | 旧玩家舱改 DeepSeek 住处，西侧旧展厅建三间住房，访客从东北港区抵达，并留未分配模块位 | 六个模型的房间 ID 与行为对应；访客至模型住处、住宅内部、扩建预留净空和场景独立存档核验 |
| W4 整体表现与发行候选 | 黑洞观景、围护、灯光、声音、角色日程与性能整理 | 第一人称＋总览同机位核验、原赛事回归、迁移存档跨进程验证、连续 30 分钟性能记录，再判断发行切换 |

验收录像应覆盖两种状态：没有赛事时也能完成一段有选择的游逛；赛事运行时可以在外围继续生活，回核心仍看到一致的结果。自动碰撞探针与真人体验分别记录。

性能先明确目标机器、分辨率和画质，再冻结帧时间与内存预算。分别取核心赛事、港区、植物密集处和黑洞观景处的测量；不能把旧场馆 RTX 5090 短段数据转成新世界的性能承诺。

## 11. 本版的决定建议

继续沿此方向施工：**以东北港区为访客入口、核心为模型住宅与擂台、外层四区为主要漫游场所**。下一个关键验收是填充抵达至核心路途的有效停留点，完成四区可持续游逛、围护、旧存档迁移和真实键鼠体验；未来加模型时优先扩建已预留的西侧住宅接口。

外围四区主题和 720 m 直径仍是可修改提案。核心承担大模型的“家”和共同的竞技活动，世界的日常空间与探索纵深由外围街区提供；西侧预留位只保证下一步能找到扩建起点，不承诺最终容量。
