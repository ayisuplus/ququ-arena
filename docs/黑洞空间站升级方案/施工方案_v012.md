版本：v012 · 2026-09-29 · 本轮为方案调整与官方资源初筛，尚未下载、安装或采用本版候选资源。

**后续制作默认先复用免费成熟组件，把工作集中在空间设计、资产适配、统一美术和实际游戏体验；没有合适免费美术资产时，用 Meshy 生成、Blender 整理补齐。**

## 1. 授权与本轮范围

用户已明确允许接下来所有迭代下载、安装组件。这是持续有效的制作授权，覆盖环境模型、材质、音效、VFX、编辑器工具和适用的程序组件；并非每轮必须引入新依赖。

- 免费、开源或账号已经拥有合法授权的合适资源，可以直接下载、安装、试装和适配，无需逐包重新询问。
- 用户随后明确“尽量用免费的”，认为缺少免费资产时更适合 Meshy 生成。因此本计划不安排新增付费组件采购，也不把购买列为推进前提。付费候选只保留参考／弃选记录；已有合法授权的资产仍可复用。
- Blender／Meshy 的既有使用授权继续有效，但“可使用”不再等于“优先从零生产”。Meshy 积分不足时的处理仍按 v011 第 6 节执行。
- 本轮交付新的施工方案、真实候选来源和项目约定；不把许可开放写成已下载、已安装或已通过美术验收。

## 2. 新的自制与复用分工

每个新工作包按“已有资产是否合格 → 社区／商店有无免费成熟方案 → 适配成本是否合算 → Meshy／Blender 补齐美术缺口”的顺序决策；程序能力缺口采用最小自研。选型按质量、覆盖范围、兼容性、性能和整合工作量比较，不为了免费强行采用低质量或适配代价过高的资源。

| 工作包 | 默认来源和实施方式 | 项目自己负责的部分 |
| --- | --- | --- |
| 空间站墙地顶、门窗、走廊、转角、管线与设备 | 优先一套风格统一的免费模块化环境包 | 第一人称尺度、四区布局、模块接口、封口与碰撞、黑洞视线；规则拼接缺口优先 Blender 精确补件 |
| 咖啡厅桌椅、柜台、灯具、通用设备和小陈设 | 优先免费家具／科幻道具包，复用已有合格资产；不足则 Meshy＋Blender | 比例、材质统一、陈设节奏、原交互锚点 |
| 三维植物、种植槽与基础材质 | 优先可近看的免费植被与 PBR 资源，不合适则制作 | 叶片透明、光照、贴图通道、种植展示和近景质量 |
| 环境音、粒子、玻璃与辅助渲染工具 | 遇到明确缺口时查成熟资源，先评估当前 URP 能力 | 事件触发、强度、音画关系和本项目性能；不先安装一整套渲染扩展 |
| 编辑器工具及通用程序功能 | 优先已有 Unity 包或维护中的组件 | 小型适配、清晰依赖方向、现有输入／UI 的接入；不为素材演示引入第二套框架 |
| 标志性建筑接口、黑洞观景结构、专属角色与道具 | 现有资产复用、Blender 精确加工，必要时 Meshy 生成 | 项目身份、原创设计、尺度与独特功能 |
| AI 比赛、评分、状态、存档和模型身份 | 保留现有项目实现 | 后端权威、事件到表现的映射、稳定 ID 与迁移验证 |

**Blender 转为以适配和补件为主，Meshy 转为以独特资产和明确缺口为主，Unity 负责装配与实际效果。** 原始资产能直接使用时，不必绕一遍导出加工；多网格、多材质、动画和复杂植被按其实际结构处理，不强塞进单网格单材质模板。

先选一套主建筑语言，再补少量匹配资源。银白舱体、深色结构与温暖生活空间仍是待参考板验证的方向；不能因为免费包方便就默认改成低多边形玩具风格。空间站外部整模也不能直接代替可漫游内装。

## 4. 当前工程的接入条件

本轮核对基线为 Git `54de46e`：Unity **6000.3.24f1**、URP **17.3.0**、Input System **1.20.0**、AI Navigation **2.0.14**，使用 Linear 色彩空间和新输入系统。来源：[编辑器版本](../../QuQuArena3D/ProjectSettings/ProjectVersion.txt)、[包依赖](../../QuQuArena3D/Packages/manifest.json)、[项目设置](../../QuQuArena3D/ProjectSettings/ProjectSettings.asset)。这些是静态工程信息，本轮未启动 Editor 或构建。

1. **小范围接入**：模型／贴图类资源先在独立测试场景检验；含编辑器自动执行脚本、全局导入器或项目设置迁移的包，先在隔离的同版本工程检查后再引入主项目。仅独立场景不能隔离编辑器脚本的副作用。
2. **保留供应商边界**：保留原始目录、`.meta` 与 GUID，不强行搬动可能有路径依赖的包；项目改动放到项目侧 Variant、派生材质或适配脚本中。UPM 包记录版本与 lock；Git 包锁定提交。记录实际使用文件和依赖，供应商更新另做候选验证。
3. **最小依赖**：先核对包内容、许可证与依赖；不导入不需要的演示控制器、菜单、联网和账户系统。只导入用到的内容及其真实依赖，不以“精简”为由漏掉着色器或贴图。原包与付费源资产的保存／共享按实际许可处理。
4. **沿用当前管线**：检查粉色材质、透明／双面、遮罩通道、法线与光滑度、光照贴图 UV、阴影、探针、实例化和 LOD。含自定义渲染功能时验证 Unity 6 的实际渲染路径。供应商演示效果与本项目实机效果分开记录。
5. **先保护业务再换外观**：优先替换视觉子对象，保持 [房间身份](../../QuQuArena3D/Assets/Scripts/Presentation/StationRoomIdentity.cs)的 `RoomId/ResidentId`，以及[咖啡交互](../../QuQuArena3D/Assets/Scripts/Presentation/StationCafeMoment.cs)的 `Counter/Seats/StableId`。不让供应商角色控制器或门脚本接管已有状态。
6. **注意现有导入器**：[ArenaArtBudget](../../QuQuArena3D/Assets/Editor/ArenaArtBudget.cs)有遍历全部 `Assets` 贴图并按名称分类的处理。组件试点只审查与修改相关文件，不执行全项目贴图重置，避免破坏供应商遮罩和透明设置。
7. **候选与存档分别验证**：[StationWorldSave](../../QuQuArena3D/Assets/Scripts/App/StationWorldSave.cs)按场景名隔离目录并显式列出迁移链。复制 W4P 成新视觉场景不会自动继承原进度；试装使用独立 QA 存档目录。确需继承时以旧档副本验证，原档保持只读来源。

不为这次选型开发通用资产管理系统或重构玩法。高内聚、低耦合落实为：供应商资源提供表现，项目组件持有业务状态，小型适配只解决实际接入问题。

## 5. 首个样板和施工顺序

仍采用 v011 的建议范围：**生活街入口 → 东南咖啡厅 → 连接短廊 → 黑洞观景台**，并核对一处空间站总览。以 W4P 为已有空间基线，实际开工时复核 HEAD；保留四区路网、邻区接口及默认发行入口。

| 阶段 | 本版交付 | 验证与完成门槛 |
| --- | --- | --- |
| A0a 真实参考与组件选型 | 查看 v011 的真实建筑／科学参考和供应商实际预览；列出现有资产、主包、辅包与必须自制的缺口 | 明确来源、素材性质、风格和可用部件；比较真实尺度与接入成本。页面无法证明的内容标为待验，不把商品宣传当项目效果 |
| A0b 最小组件试装 | 一套主建筑候选的直段、转角、门框、窗、地顶及少量主陈设；中性测试场景与测试记录 | 当前工程版本下编译、材质、尺寸、碰撞、贴图与必要依赖通过；核对导入差异，没有意外修改全局设置。暂不可获取的候选保留待验 |
| A1 组装样板与补件 | 在独立候选场景装配完整墙地顶和主要陈设；Blender 补接头／收边，Meshy 仅处理明确缺口 | 第一人称近看、侧看与连续通行成立；业务锚点、邻区接口和黑洞景观保持；逐件登记采用／返工／弃选 |
| A2 完整视觉样板 | 统一材质、照明、反射、玻璃与黑洞构图，输出固定机位对照和独立 Windows Player | 沿用 v011 的连续键鼠漫游、相同观看条件、目标硬件性能和用户审美认可门槛；有实际成品后再确认样板方向 |
| A3–A5 扩展与体验深化 | 将验证过的模块用于抵达展示路线和四区，按最终空间完善生活交互 | 沿用 v011 的逐区视觉、整体赛事与存档、持续性能和发行验收；正式样板未通过不全面铺开 |

下一轮先做 **A0a＋A0b**，产出“免费组件对比＋最小可运行试装”后继续样板装配。常规下载、安装和制作自主推进；免费资源不合适就沿用已授权的 Meshy／Blender 补齐，样板审美认可针对实际可看的成品。

## 6. 验收、记录与回退

- **视觉**：先统一参考、比例、纹理密度、材料响应和灯光；保留入口、咖啡厅、短廊转角、观景台同机位前后对照及运动观看。现成资产仍需本项目视觉验收。
- **运行**：Editor 编译和相关 Console 无新增错误，构建后用实际键鼠走完该段路线。静态装饰只做加载与视觉核对；改几何再加碰撞、交互距离和安全落点；改脚本再加对应行为测试，不每次重跑所有历史测试。
- **性能**：沿用 v011 的实际 CPU／GPU／内存／分辨率登记和 2560 × 1440／60 FPS 建议起点；比较同路段帧时间、较慢帧、内存／显存与样板阶段 30 分钟趋势。大包和高面数不自动等于高质量，未测硬件不作通过承诺。
- **记录**：每包登记来源、作者、许可／归属、版本、下载日期、原包哈希、导入路径、实际依赖、派生资产、采用／弃选理由及本项目验证结果；无须保存账号凭据。区分“已筛选、已获取、已导入、运行通过、视觉通过、用户认可”。
- **回退**：导入前记录工作区和场景基线，一包一项可追踪变更；验证后合入候选，失败只回退本包引入的内容。原场景、存档、历史资产和必要弃选证据保留。默认发行切换仍须完成原有验收。
- **Git**：自动提交本轮可归属的正式改动，保留包版本锁与许可记录。当前原有 `ArenaFont.asset` 修改单独保留，不纳入本轮方案提交。素材源文件按许可与现有 Git LFS 策略保存，不提交缓存、凭据及无关构建副本。
