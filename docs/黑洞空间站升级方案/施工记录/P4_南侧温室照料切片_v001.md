# P4 南侧温室照料切片 v001

日期：2026-09-28。状态：独立候选世界的一个可到达、可重复互动的日常目的地；尚非完整 LOC-03 公共区或 P4 的 20 分钟循环。

## 依据与落点

[施工方案 v008](../施工方案_v008.md)将 LOC-03 放在外方南侧，并要求温室可检查、浇灌、有外观反馈且进度可保存。最初[空间站总览图](../08_概念图/IMG-001_空间站总览_v001.png)继续决定外方、内菱形连桥、中央环和坠落井的关系。本轮只在现有南侧主路旁、结构柱东侧增设一个约 24 × 14 m 的支房（x 20…44、z -118…-104）；北向入口接 z -100 主路，不改中心井、平台或主通行网络。玩家可从东侧居住舱沿连续地面抵达。

装置参考 [NASA Veggie](https://www.nasa.gov/exploration-research-and-technology/growing-plants-in-space/) 的六个种植枕及植物照料，[NASA 的舱内操作说明](https://www.nasa.gov/missions/station/veggie-plant-growth-system-activated-on-international-space-station/)提供补水与 LED 的真实依据。游戏中的公共温室尺寸和布置由概念图及步行路线决定，未复制 NASA 设备或导入其图片。图形仍是自制几何灰盒：六个种植位、叶片簇、灯带和控制台，只检验可读性与动作反馈。

## 实施

- `StationGreenhouseCare` 以稳定 ID `south-greenhouse-veggie-01` 管理检查 → 补水 → 完成的循环；E 键在控制台 3.5 m 内操作，远处拒绝。首次补水后叶片簇变大，每次完成计数加一，不增加真实时间等待。
- `StationWorldSave` 在现有版本 1 候选世界文件中增添可选 `greenhouse` 字段。它仍独立于赛事后端和角色自定义，保存玩家安全位置、北侧双货台和这一处温室状态。旧版 v1 文件缺少该字段时以未照料状态进入；带有无效温室字段的文件仍拒载。
- 场景和材质通过当前 Unity Editor 保存；构建入口检查温室组件、稳定 ID 与存档引用。没有替换默认发行场景。

## 验证与边界

[同一 Win64 构建的原始结果和可见画面](../../validation/station-greenhouse-2026-09-28/README.md)：从玩家舱使用 `CharacterController.Move` 分 856 步走完 214 m，逐步检查地板和碰撞；远处操作拒绝，近处检查、补水、叶片反馈与写盘通过。退出并重启 Player 后，位置和进度恢复；第二轮完成并再次重启仍保留计数。上一轮无温室字段的 v1 候选存档成功载入并补写字段。原有北侧接驳、观景台、货运工单 Player 探针回归通过。

探针直接调用交互方法，未模拟真实 E 键；本轮画面只证明灰盒动作反馈，不是最终植物模型、灯光、材质或完整公共温室体验。长椅、居民相遇、观景摄影、下层连接和真实键鼠完整漫游还需后续施工。当前地图的 240 m 方形层仍是小规模开放世界的核心灰盒，并非最终地图边界。
