# P4 双居民房间—客厅日程切片 v001

日期：2026-09-28。状态：独立候选世界中的两位样板居民可以在各自房间与东侧公共客厅之间往返，并在近处提供固定短对话；仍不是完整 NPC 日程或 20 分钟生活循环。

## 依据与范围

[施工方案 v008](../施工方案_v008.md)要求主层、上下层和站外设施构成连续的小规模开放世界，LOC-09 东侧客厅与居民街区相接，居民能从房间前往公共空间、不能穿门堵路，也不能与同名参赛实体同时可见。[最初总览图](../08_概念图/IMG-001_空间站总览_v001.png)的外方框、内菱形和中央环仍是整体锚点。本轮只复用已有 `resident/chatgpt`、`resident/claude` 房间与工程内的角色外观，没有增建房间或新造角色美术。

## 实施

- 两个 `StationResidentRoutine` 分别绑定稳定房间 ID，沿经过碰撞验证的固定走廊往返各自房间和客厅。起居等待时间错开；客厅停留面向公共区域，靠近后按 F 可读固定两句短信息，其中赛况来自 `ArenaStationLiveMatch.Status`。
- 生活角色使用工程既有的 Gallery 模型与动画控制器。它们不加入赛事计分、赛题或选手控制链。`ArenaStationLiveMatch.HasVisibleFighterPreset` 只向日程组件提供同名可见选手状态；选手出现时隐藏相应生活角色并关闭其碰撞，离场后恢复。识别同时考虑模型身份和当前外观预设。
- 两位居民与咖啡交互仍处同一可步行场景；已有赛事后端继续决定胜负。默认发行场景未切换。

## 验证与限制

[原始证据](../../validation/station-residents-2026-09-28/README.md)记录了 Editor 和独立 Win64 Player 的路线、地板、最近间距、短对话、选手避让，以及新构建上的咖啡厅路线回归。隔离本机免费 mock 赛事实际产生选手并完成结算：在同一赛事 `cc9aa0049-7866-4d2c-ba0c-01c43fe4c5bc` 的战斗阶段，ChatGPT 生活实体隐藏；选手离场后在客厅恢复。评分和赛事数据仍来自原后端。

原客厅座位朝井下黑洞的射线 1.52 m 后命中主层楼板；单靠调相机不能得到概念图中的真实黑洞窗景。读盘调查还发现环台内沿 `(17, 6, 0)` 到井下目标无碰撞遮挡，说明实体高位观景点在几何上有可能，但尚未修建、验路或做视觉验收。这一结构选择待按概念图决定，不能用贴图假窗代替。

当前日程只在两个房间和客厅之间循环，探针快进同一更新函数而非完成真人长时间漫游；实际 F 键操作、玩家让路时的拥堵恢复、离屏低频更新、座椅占用、NPC 日程跨会话保存及候场／观战节点仍待后续施工。截图中的房间和客厅仍是灰盒，不能视作最终空间或 3A 表现验收。
