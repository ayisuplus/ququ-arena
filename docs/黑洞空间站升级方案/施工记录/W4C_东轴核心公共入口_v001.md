# v010 W4C：东轴核心公共入口与后续扩建边界

W4A 让访客从东北港区抵达，但审计发现东向主路走到旧核心墙边便被挡住。W4C 在 W4A 的独立副本中将东墙分段，安装默认关闭的公共门；玩家从港区沿主路到门，开门进入核心公共走道，再绕过既有结构柱抵达竞技场一侧。墙外原有南北向绕行仍可走。六间现有大模型住处、DeepSeek 接收的旧玩家舱、西侧未分配 7 × 6 m 模块和封闭住宅支廊保持原位置。

这一步对应用户的“现有区域作核心，外围才是漫游区”，不是把核心继续放大。实测港区到门 265 m，门到竞技场侧公共地板约 70 m；独立 Windows 包走完全段累计 336 m。原 240 × 240 m 核心继续是模型住处和擂台；东轴是外围进入核心的一个清晰接口。东南生活、西南花园、西北科研、东北港区的内容仍须在核心外加密，不能把这条通路的长度当作可玩性。

## 以后扩建按哪些边界接

1. **空间**：四条径向公共主路、外环分段和四区根节点是接入关系；720 m 直径只是候选。新街区沿对应外侧段向外接，不缩放旧核心、不覆盖现有道路，也不把房间或赛事机械区当作捷径。每加一段，验证它能从已有路到达、能绕行或返回，且旧通路仍通。东西南北另外三个核心公共出口尚须逐个验证，不能凭东门认定四门完成。
2. **住宅**：房间身份跟模型稳定 ID 走，不跟房间坐标走。现有六间并非容量上限；先使用西侧未分配模块，再从约 `(-96, 0, 55)` 的封闭支廊接口分段外接。每段都要有共享廊、门禁／围护、居民可走日程和可验证的访客安全落点，不占中央井、擂台动态空间或十字主路。
3. **存档**：W4C 当前仍以场景 ID 隔离存档，并只读导入 W4A／W3V2。会重新封闭的门洞用场景内的 `StationUnsafeSaveZone` 标记，安全位置校验不写死门坐标；以后新增同类门洞应加同样标记。下一个独立场景若改变可走地板、房间或出生点，必须先列旧安全点映射，测试目标档优先、旧档保留、损坏源不越级、跨进程恢复，然后再推进默认入口。场景名耦合是当前明确的迁移工作量；本轮没有宣称“随意扩建也自动兼容”。
4. **围护与性能**：东门目前只有开关碰撞，没有空气交换模拟；街区边界与实际压差分舱需和未来外层围护一起做。街区按可单独检查的根节点布置，先测视线、帧时间和内存，再决定是否引入增量加载；本轮没有为未测量的优化搭框架。

证据在[W4C 验证页](../../validation/station-east-gate-w4c/README.md)。入口、存档与旧场景回归已过灰盒／隔离 Player 门槛；实际键鼠、正式视觉参考、四区游逛密度和发行门槛仍开放。
