# P4 候选世界安全存档 v001

日期：2026-09-28。状态：独立候选场景的第一份世界状态；尚非 P4 日常闭环或正式发行存档。

## 责任边界

依照[施工方案 v008](../施工方案_v008.md)第 7.3 节，新增 `StationWorldSave` 只保存候选世界的玩家安全位置和北侧两组货运工单。赛事结算仍由现有后端负责，角色自定义继续使用 `ArenaPreferences`，两者的数据不复制进世界存档。

货运组件提供可验证的状态快照，世界存档负责文件写入与恢复；每台货运控制台使用 `north-dock-left`／`north-dock-right` 稳定 ID。文件有显式版本号与场景 ID，先写 `.tmp` 再替换主文件并保留 `.bak`；主文件损坏或载入位置危险时尝试备份。测试运行从命令行指定隔离目录，普通候选 Player 写入自己的持久目录。

安全位置只在有可步行实体地板支撑时更新；中央 72 m 环台附近、货箱运行轨道、升降板、栏杆、屋顶、轨道和墙顶不作为普通载入点。已对玩家舱、北侧接驳区、上层 promenade 和下层 observation corridor 抽样验证。快照含货箱运动阶段与位置；本轮实测了检修检查和完成状态的跨进程恢复，运动中退出仍待专门验证。

## 验证

- Unity Editor 从磁盘重开场景：存档组件绑定玩家与两台货运设备，两个 ID 不重复；脚本编译通过，Win64 隔离构建成功。
- 分次启动 Player 验证写入、主文件载入、损坏回退、中央井危险坐标回退、工单完成后重启、上层与下层安全位置重启；全部退出码 `0`。[原始结果与样例文件](../../validation/station-world-save-2026-09-28/README.md)。
- 原有世界 Player 探针回归通过，QA 自动保存落到自己的结果目录，不覆盖正常候选档案。
