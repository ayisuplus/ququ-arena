# 黑洞空间站：场景视觉优先施工方案

版本：v011 · 2026-09-29 · 本轮交付为方案，尚未开始本版美术施工。

**下一阶段目标：完成一段视觉完整、能够自由漫游的黑洞空间站样板；样板得到用户认可后，按同一质量标准扩展世界，再逐步完善生活交互。**

本版承接 [v010](施工方案_v010.md) 的第一人称、中央住宅与擂台、外围十字四区和东北港区抵达方向，替代其施工优先级与阶段验收顺序。历史方案、已有场景、模型身份和赛事规则继续保留。720 m 外径仍是候选尺度；集中制作样板不代表缩小最终世界，最终尺度仍按后续空间与视觉验证确定，也不把一间咖啡厅当作完整游戏。

## 3. 视觉方向：宏大外景与可停留的日常空间

建议以“黑洞上方可以生活的空间站”为统一方向。大尺度上读得到核心、四区、层叠结构与黑洞；眼高上读得到门窗厚度、家具尺度、材料触感和照明来源。两种尺度同步设计。

- **建筑**：延续银白舱体与深色承重结构，补完整墙地顶、结构厚度、转角、接缝和门窗收边。控制可见大平面的连续长度，避免四区全部变成同一种玻璃走廊。
- **生活空间**：用暖光、织物、家具和三维植物形成停留感。灰色墙面上添加发光条不足以完成室内氛围，灯具必须与真实受光关系一起制作。
- **材质**：让金属、涂层、织物、玻璃、地面和叶片在中性灯光下就能区分；控制磨损尺度，不把所有表面做成同样的脏灰反射。
- **黑洞景观**：让室内前景、结构中景和黑洞远景共同构图。到窗前、侧移、转头时都应成立；不靠强制切换摄影机才能看见项目的核心景观。
- **空间节奏**：入口有识别点，室内有明确重心，短廊有明暗与开合变化，观景端点有视野释放。空白和陈设都服务于这段行走体验。

上述为本版美术建议，正式造型、配色和材质以实际参考图与样板比对确定；现有概念图是意图参考，不能直接视为可施工图或已完成的游戏画面。

## 4. 首个样板的施工边界

建议从 W4P 复制独立候选场景，在同一世界坐标下制作东南样板。开工时复核实际 HEAD 和未提交工作，不机械使用本版写作时的版本；现有 `ArenaFont.asset` 修改属于前置工作，不混入场景提交。

```text
既有生活街入口 → 咖啡厅 → 有转折的连接短廊 → 黑洞观景台
                     ↘ 保留既有公共回程与相邻区接口
```

| 范围 | 必须完成的观看体验 |
| --- | --- |
| 入口与街道一小段 | 从正常眼高看得出入口、建筑体量和方向；入口附近不出现明显断头构件 |
| 咖啡厅 | 地墙顶完整；柜台、座椅、桌面、灯具、植物和设备有统一比例与材质；家具近看无明显穿帮 |
| 连接短廊 | 连续通行、顶棚与围护成立，结构接缝自然，转角形成下一处景观的预告 |
| 黑洞观景台 | 不被实心楼板／窗框切掉主要景观，窗前侧移仍成立，玻璃与室内反射不淹没黑洞 |
| 样板可见的远景 | 统一核心与邻近结构的可见轮廓、色调和深度；远景代理明确登记，不能当作其他区已完成 |

A0 同时检查一个空间站总览机位，保证局部建筑仍属于同一个宏大世界。近景优先投入真实模型与材质；总览负责轮廓、比例和黑洞关系，不要求这一阶段把四区所有内部做完。

保留可走的接口、房间与角色 ID、中央井和赛事机械净空。样板预览可以设置独立评审起点，正式世界的访客起点仍在东北港区。不为缩短评审路线擅自改动默认发行入口。

## 5. 资产工作包与工具分工

**Blender 负责可控的空间、尺寸与最终整理；Meshy 负责需要独立造型的资产候选；Unity 负责实际材质、照明、装配与运行效果。** 三者使用规模由视觉质量和实际需要决定。

| 工作包 | 交付内容 | 主要制作方式 | 核查重点 |
| --- | --- | --- | --- |
| 建筑模块 | 地板、墙板、顶板、立柱、门窗框、转角、收边、护栏、连接口 | Blender 精确建模，统一模块接口 | 尺寸、厚度、接缝、法线、轮廓与通行 |
| 咖啡厅主陈设 | 柜台、共享桌、座椅、设备墙、吊灯／壁灯 | Meshy 生成造型候选，Blender 调整与装配；已有合适模型可复用 | 人尺度、落地接触、近景造型和材质一致性 |
| 三维种植 | 植物、种植槽、局部灯架与维护结构 | Meshy 候选＋Blender 叶片、透明、层次与网格整理 | 行走侧看有体积，叶片不成厚块，透明排序可靠 |
| 观景构件 | 观景窗、框景结构、停留座位、局部设备 | Blender 推敲视线与精确接口，Meshy 可供独立道具 | 黑洞可见面积、侧移构图、护栏与窗框遮挡 |
| 小陈设 | 杯具、咖啡设备、书刊、维护物件等有明确用途的物品 | 按镜头需要复用或生成，Blender 整理 | 增加生活痕迹，不堆满通道或画面 |
| 材质与贴图 | 涂层金属、结构金属、地面、织物、玻璃、植物等 | 整理生成贴图，补必要法线／粗糙度等通道，在 Unity 中统一响应 | 纹理密度、色彩空间、材质差异和移动中的稳定性 |

先完成建筑与主陈设，再添加小物。已有资产逐件按新样板的质量审核，合格就复用；质量不够可重做，不因历史投入强行保留不合适的成品。

允许多对象、多网格、多材质、独立碰撞代理与不同精度版本。现有 game-production v0.1 的单网格单材质模板只用于适合的静态道具；不能为套模板合并掉玻璃、金属、织物或植物的职责。生成结果若不适合近看，就在 Blender 修整或保留为弃选，再做下一候选。

不预设生成次数、资产总数或统一面数上限。面数、贴图尺寸、材质槽、LOD 与透明叠层按实际镜头距离和性能测量确定；资源充足仍应保持清晰的视觉重心与可管理的工程结构。

## 6. Meshy 授权、消费记录与不足时的处理

本项目本次环境美术制作的 Blender／Meshy 使用不设人为总额度、调用次数或候选数量上限。已明确的授权不需要每次生成重新询问。

1. 正式制作前检查实际 Blender 连接、Meshy 登录／可用余额和 Unity 工程状态。本轮仅写方案，未核验当前服务可用性、余额或价格，也未产生生成消费。
2. 每批先依据当前 CLI 帮助与服务报价做可用的无付费估价，登记预览、细化、贴图等所需步骤。估价用于掌握余额和安排任务，不额外设定本次授权之外的总预算。
3. [旧项目配置](../../game-production.json)的 `asset_id: jade-champion`、`max_credits: 65` 属于旧奖杯任务，不约束本次环境制作。本轮不修改这份历史配置。实施时为本次任务使用独立配置；若 CLI 必须接收数值上限，按该次操作核实的完整报价填写，不猜测 `0` 或 `null` 表示无限。
4. 每次提交保存稳定操作标识、实际任务 ID、提示词、参数、预估／实际消费和输出位置。超时继续查询原任务；提交结果不明先核对任务列表，避免重复收费。消费无法核实时记为未知，不写为零。
5. **检测到积分不足或服务返回余额不足时，立即停止新增收费请求，暂停依赖该结果的制作并向用户报告。** 已提交的任务保留原 ID，可查询和收回已完成产物，不重新提交；不自动购买积分、不更换账号或生成服务来绕过不足。
6. 报告包括：正在制作的资产、任务阶段与 ID、服务返回的余额和所需积分（不可得则注明未知）、已完成文件、失败信息和待续部分。用户处理额度并要求继续后，从现有记录恢复，不从头重复生成。
7. Blender／Meshy 未启动或无法访问时，报告实际缺失环节；可以继续不依赖该服务的文档或资产整理，不私自换成网上找到的流程。外部桌面操作按用户要求先通知，网页优先使用内置浏览器。

## 7. 材质、灯光与渲染施工顺序

沿用现有 Unity／URP。先得到可靠的材质与照明，再调整后期；管线迁移只在有具体无法解决的问题时另行评估。

1. **固定观看条件**：登记眼高、视场角、目标分辨率、画质和相机机位。以现有约 1.63 m 眼高为核查起点，门、扶手、桌椅和通行尺度用第一人称实走复核。
2. **建立中性材质样板**：检查模型尺度、UV、法线和贴图；将金属、墙面、地面、织物、玻璃、叶片放在同一中性光照中比较。正确转换粗糙度／光滑度与金属通道，不丢失有效信息。
3. **建立实际照明**：从主要灯具和窗景确定明暗关系，再补环境光、局部阴影与反射；发光材质和真实受光相互对应。静态与动态对象分别选择合适的烘焙／探针方案，先在样板验证。
4. **处理玻璃与黑洞**：检查室内外亮度差、透明叠层、框架遮挡、代理体和裁剪边界。保持吸积盘层次，避免靠过曝或强 Bloom 掩盖缺少材质细节的问题。
5. **统一曝光和后期**：最后调色调映射、曝光、对比、适度泛光与抗锯齿，保证明暗空间衔接和行走时稳定。避免强景深或镜头效果妨碍第一人称观察。
6. **按证据优化**：记录黑洞窗景、玻璃叠层、植物密集处和咖啡厅的实际开销，再处理 LOD、贴图、阴影、实例化与可见性。不预先大改引擎架构。

## 9. 验收如何避免再次偏向功能数量

### 9.1 每轮美术迭代

- 保留修改前后相同机位、相同曝光与分辨率的对照；机位至少覆盖入口、咖啡厅、转角和观景端点。
- 同时查看运动中的侧面、背面与接缝，记录保留／返工／弃选及原因。仅有一张好看的截图不能覆盖整段体验。
- 只检查本轮改动涉及的加载、碰撞、视线和状态风险。单纯材质或灯光迭代不要求重复整套四区存档与居民回归；改变地面、门、路线或 ID 时才追加相应回归。

### 9.2 样板阶段完成

1. **视觉**：真实 Player 中建筑、模型、材质和光照形成整体；关键视野内无明显灰盒占位、风格冲突或错误遮挡。关闭调试界面后仍能理解空间并愿意停留。
2. **漫游**：在正常 Player 窗口用实际键鼠完成一段连续路线，包含进入、停留、侧移、转头与返回；无传送拼接或强制镜头补救。脚本探针与离屏图另行标注。
3. **性能**：A0 登记实际可测的 CPU、GPU、内存、分辨率和画质；建议以 2560 × 1440／60 FPS 为样板起始目标，开工时根据机器复核。预热后记录代表路线的 CPU／GPU 帧时间、较慢帧分布、显存与 30 分钟运行趋势；GPU 数据取不到就注明。只有实际测到的机器可以宣称通过，4K 或其他显卡需单独验证。
4. **状态**：验证正常启动及样板涉及的咖啡／赛事显示仍可使用；几何或安全落点变动时验证载入位置。原存档保持只读来源，迁移用副本核对，不让每次纯美术修改都新增一套存档版本。
5. **审美认可**：交付实际画面与可打开的预览，用户确认样板方向后进入全面扩展。认可的是这个阶段的成品范围，不把局部通过写成全世界完成。

技术通过、视觉通过、用户认可分别记录。没有条件完成的项明确写为待验，不用“构建成功”“路线走通”或“模型生成成功”代替。

## 10. 产物、记录与 Git

每一项资产按实际制作链保留适用的源文件与记录：Meshy 生成资产保留原始结果、生成记录、候选与弃选原因；Blender 加工资产保留可编辑 `.blend`；直接复用资产记录来源。登记源贴图、导出版本、Unity 材质和 Prefab 的对应关系。加工输出另存，避免覆盖唯一源文件。

制作开始时沿用现有 `.game-production/runs/` 记录运行任务；在 `production/black-hole-station/` 下建立本次视觉制作的独立源目录，Unity 正式资产进入清晰的样板目录。具体文件名与路径以首次创建时登记为准，本方案不把尚未创建的文件列为已有交付。

样板交付包包含：

- 参考与美术方向说明、资产清单及来源；
- Blender 源文件、整理后的模型与贴图、Unity 场景／Prefab／材质；
- 固定机位对照、同一构建的连续漫游录像、必要技术与性能记录；
- 可运行的独立 Windows 预览及完整伴随文件；
- 当前消费、未完成事项、已知问题和下一轮具体修改点。

阶段完成后自动提交本轮可归属的源代码、文档和正式资产；大型源文件沿用仓库实际策略。运行缓存、凭据、账户数据和不必要的构建副本不混入提交；检查已有脏文件并单独保留。历史场景、存档与拒绝候选不因版本升级自动删除。
