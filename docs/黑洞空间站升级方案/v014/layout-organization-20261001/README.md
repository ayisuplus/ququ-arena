# 建筑位置、组团边界与零散部件归属：讨论稿 01

2026-10-01。用户确认本轮先定建筑位置、建筑群边界与零散部件归属，再讨论外形。本稿是可调整的规划建议，尚未移动、停用或重新挂接任何场景对象，不是施工批准。

建议把中央核心周围的附楼收拢为四个组团，每组明确主馆、附楼、入口前庭和附属设施。四角斜向主路、外环及登船轴线作为公共交通空间；它们经过某个区，不等于属于该区的建筑。先理清归属再讨论拆并，避免继续用新屋顶、新围挡掩盖旧构件。

## 现状依据与问题

- 本轮通过已连接的 Unity 6000.3.24f1 / Pipeline 读取当前候选 `Assets/Station/Scenes/Candidates/BlackHoleStationEcologicalGardenV014.unity`。场景处于 Edit、未修改状态；64个根对象、14,664个Transform，抽取113条主要分组记录和148个激活座位锚点。数字不等于建筑数量。
- 本轮布局讨论对象是4个主功能区与8栋附楼：6栋公共楼、2栋短住舱。另有中央核心住处、看台、登船厅与船体、上层通廊、下层观景设施，不能把这12个讨论单元当作全站建筑总数。
- 六栋公共楼并非毫无秩序：北、南各两栋，东、西各一栋。问题是附楼与主功能区之间空隙较大，短住舱又偏离主区；缺少明确的入口前庭和连续街道边界。从平面看是多组单体，从实景看又叠加了很长的连廊与高位结构。
- 场景层级主要按施工批次组织。例如咖啡厅的围护、前庭、座椅、精装分属多个根节点；同一根 `V013 P1P2 finished joinery` 还可能包含不同区的构件。因此不能只移动“楼房模型”，也不能依据 `V012`、`trial`、`graybox` 等旧名称就判断可删。
- 已实际查看北厅、西研究馆和短住舱的既有实装图。北厅截图中多层长框架与连廊叠加，西研究馆旁附楼和独立铺装的关系也较弱。这是本稿的视觉判断，不等于全部零件均已逐件鉴定。

基础边界继续采用现行v014：连续圆盘（本轮实测甲板包围盒约±336m）、240m中央方形核心、中央赛场、原住处保留；植物集中在南侧玻璃生态园。配色与外形本轮不设计。

这些边界是**建筑群管理与视觉收束范围，不是新围墙、甲板切口或允许整片删除的范围**。楼间前庭、各组到外环的连接仍需保留。已有下层入口、真实落差护栏、公共休息点可在边界之外，由公共交通负责。

本稿选择“小范围收拢、保留四侧功能与八栋附楼”的方案。它能复用现有室内与交互，但不会立即消除全部高位框架造成的杂乱。若只移动六栋楼而不处理附属构件归属，改善会很有限。合成四座大体量建筑会涉及新的外形与室内重构，留到下一阶段讨论。

## 核对结果与后续施工条件

本轮完成的是规划资料，不做Unity重建或Play验证。`diagram-checks.json`检查了八栋附楼建议包围盒落在拟定组团内、不侵入中央核心、不互相重叠，也不与图中四个主功能设施的调查包围盒重叠。该检查**没有覆盖全部既有物体、路径、光照、行为引用或安全净空**，不能证明建议坐标已经可施工。

下一步实施按三个独立小包推进，每包都使用候选副本并保留旧档：

1. 完善R01–R10的逐件归属：核对可见构件、脚本引用、碰撞、稳定ID及真实通行用途，确认收起候选；交付可定位清单。
2. 按讨论确定的坐标迁移完整建筑包：先测目标范围与路线，再整体移楼，连同入口、家具、座位、门、探针、静态光照和外部引用一起处理；旧场景和旧存档保留。
3. 分批收起无用途构件：先验证替代地面与路线、落差护栏、交互和存档恢复，再停用。用同机位俯视、四向人视点与场景层级检查空间是否清楚；技术验证与用户视觉认可分别记录。

本轮只提出“紧凑四组团”与六栋附楼的小范围移动。尚待讨论：是否接受这种收拢程度，以及高位框架逐件审查后应保留的视觉层次。建筑外形、材质和新增资产留待该布局确定之后。
