# 多模型工作台：实现与验收

2026-09-12。桌面个人工作台，沿用已确认的深蓝黑、青色边线、黄绿色操作按钮。设计参考图保存在 [design/cyber-workbench-concept.png](design/cyber-workbench-concept.png)。

## 已实现

- 首页提供赛前题库、阵容、题数和解说席配置；阵容及选项本机记忆。后续流程简化后默认五题、解说关闭，用户可在“更多设置”或对战中开启。
- 参赛窗口按树状布局拆分：拖到边缘拆分，拖到中央合并标签；支持横纵分隔条拖动/键盘调节、最大化、隐藏和恢复。布局按阵容保存在 localStorage，数量没有固定上限，最小阅读尺寸不足时工作区滚动。
- 公开推理/摘要与答案分开展示，未提供推理时明确标注。重试使用独立调用序号，先前输出可展开。历史题目选择、向上阅读、引用追问均能暂停题目跟随；输出增量不会强制把正在阅读的历史滚回底部。
- Web 比赛逐题同步，最多 8 路调用；剩余模型等待容量。暂停在题间生效，终止取消模型与裁判请求。中止记录和公开时间轴落盘，生涯结算入口也明确排除中止记录。
- 独立文字解说席支持 Codex/Claude 检测、开关、切换、公开摘要、点评和引用追问。每 10 秒合并新增赛事进展，跨题合并保留前题数据，无更新不调用；用户追问优先于下一段自动点评。
- 评分仍由原裁判产生；解说标为“分析”。每题结束后才向解说提供标准答案和裁判说明。解说失败不会改变参赛调用或评分，也不会自动换 Agent。
- SSE 快照保存完整公开文本、文本块、历史题目与各次重试，独立于旧 500 条事件缓冲。刷新复用当前 session；服务重启后的旧 session 提示打开回放，不自动新开赛。
- 每场新比赛生成 `timeline-<uuid>.jsonl`，战绩通过 `timelineFile` 引用；新回放按时间轴恢复公开输出与解说，旧战绩按已有答案和评分回放。中止战报标注部分记录。

## Agent 接入与限制

参考 OpenDesign 的定义、进程与协议分层思想，没有将上游整个 daemon 引入项目：

- [适配层说明（固定提交）](https://github.com/nexu-io/open-design/blob/ad9078b87c2d08e537ca3e041c46c124e7380c9c/docs/agent-adapters.md)
- [Codex 适配](https://github.com/nexu-io/open-design/blob/ad9078b87c2d08e537ca3e041c46c124e7380c9c/apps/daemon/src/runtimes/defs/codex.ts)
- [Claude 流式解析](https://github.com/nexu-io/open-design/blob/ad9078b87c2d08e537ca3e041c46c124e7380c9c/apps/daemon/src/runtimes/claude-stream.ts)

本项目 `agents.ts` 定义 Agent、实际执行文件、登录与参数检测；`agent-session.ts` 管理子进程、stdio、原生会话与统一事件；`commentator.ts` 负责赛事数据与点评调度。界面只消费统一赛事事件与 Agent 状态。

Codex 通过 App Server stdio JSON-RPC，启动 `read-only` 会话，关闭 shell、code mode、应用、插件、MCP、hooks、多 Agent 与图像生成等工具能力。Claude 使用双向 stream-json，探测增量参数，工具集合置空、严格空 MCP 配置并禁用 hooks/slash commands。Windows 使用实际可执行文件与参数数组，长赛事上下文经 stdin 传递，程序不修改用户的 CLI 配置或登录数据。

## OpenRouter 免费目录与自定义阵容（2026-09-12 首轮记录）

首页阵容已改为可搜索、多选的列表，默认打开 OpenRouter 免费模型页，另有自定义、模拟模型和其它已配置供应商。支持厂商筛选、已选标签移除、清空、刷新后保留选择；主开赛、每日一擂、录制台及题库卡片共用同一阵容。新增或编辑自定义模型后自动选中，关闭配置弹窗后可继续开赛。

以上是首轮交付状态；下方“模型管理与开赛流程简化”记录当前行为，已移除在线模拟模型、取消多处开赛入口，并保留编辑前的选择状态。

`openrouter.ts` 从 [官方模型 API](https://openrouter.ai/docs/api/api-reference/models/get-models) 获取目录，服务端缓存 5 分钟、合并并发请求，前台每 5 分钟更新并提供手动刷新。实际联通时得到 **19 个免费文本模型**（当前快照，数量随官方目录变化）。输入必须支持文本、输出必须仅为文本，所有列出的计价项目均为 0；排除音乐输出及 `openrouter/*` 随机路由，以保持选手身份确定。卡片显示上下文、推理支持与官方详情，另有 [账号额度说明](https://openrouter.ai/docs/api/reference/limits)。

首页发起的 OpenRouter 比赛带免费模式：开赛强制刷新核验，每次调用检查目录有效性，并按 [官方供应商路由参数](https://openrouter.ai/docs/guides/routing/provider-selection) 设置 `max_price` 的输入、输出、请求和图片费用上限为 0。模型变价或下架后，已选标签保留并标记不可用，用户自行调整阵容；目录更新失败保留历史列表，暂停免费模型开赛。不会自动替换成其它模型。

`model-settings.ts` 负责本机配置与原子保存，`model-api.ts` 提供同源本机配置接口，`model-picker.js` 负责选择与编辑。OpenRouter 只填写一个 Key；自定义模型使用 OpenAI 兼容 HTTP 接口，可指定名称、模型 ID、地址、可选 Key 与流式开关。比赛启动时固定配置快照，之后编辑不改变在途调用。Key 仅在服务端配置与请求头使用，接口返回保存状态，不回显密钥；战报和浏览器阵容存储不包含 Key。配置路径及环境变量见 [接入说明](../arena/README.md#接入真实模型)。

新增接口：`GET /api/models`（`?refresh=1` 强制同步）、`PUT /api/model-settings/openrouter`、`POST /api/model-settings/custom`、`PUT/DELETE /api/model-settings/custom/<custom:id>`。

## 多色竞技灯光与动效（2026-09-12 后续）

场景从单色染色升级为多色灯光：保留赛事状态色，在视频上叠加青色、紫色、玫红及黄绿射灯、缓慢漂移的光晕、细激光线和小光点；底部光带流动，开赛与完成各有一次扫光。模型窗口采用八种鲜明代表色，边框、标题栏、编号和输出状态与所属模型一致，正文颜色保持稳定。首页也增加多色环境光、选中行标识与开赛按钮扫光，布局与操作路径不变。
