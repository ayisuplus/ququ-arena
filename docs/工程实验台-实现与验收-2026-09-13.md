# 工程实验台：实现与验收

已实现仓库修复赛道的首版。新页面为 `/experiments`，原有短题、开放题和多轮文本比赛继续使用原来的入口和数据。

## 使用流程

1. 在“实验台”选择工程任务、已登录的 Codex 或 Claude、执行预算和重复次数。
2. 开始实验。每个 Agent 的每次重复都从相同的任务快照建立独立容器；依次运行，重复时轮换 Agent 顺序。
3. 在同一个实验记录中查看执行轨迹、文件变更、正式验收、产物和冻结协议。全屏观看使用同一记录，不会重新调用模型。
4. 在“实验记录”比较相同任务与执行条件的结果；也可进入“文本实验诊断”，对旧文本战绩进行同卷配对比较和按版本分组的题目诊断。

首批 6 个任务：重复入账、事件快照统计、TTL 缓存、分页、依赖排期、CSV 导出。全部使用原创合成开发材料，包含完整需求、公开测试和固定验收条件。它们是公开开发集，不标为人工金标准或保留验证集。任务定义位于 `arena/src/engineering/tasks.ts`；原有可编辑文本题库继续可用。

## 执行与证据边界

- 本机原生 Agent 使用现有登录；只暴露项目自己的 `list_files`、`read_file`、`write_file`、`run_checks` 四个工程工具。解说与正式文本评分仍使用原有只读、禁用工具配置。
- 文件和测试工具仅操作任务容器。容器关闭网络、无宿主工作区和 Docker socket 挂载，使用非 root 身份、只读根文件系统、1 CPU、512 MB 内存、64 进程限制及有界临时目录。
- 允许修改 `src/solution.ts`，公开测试与清单中其他文件不能通过工具修改。用户密钥不进入容器。
- 默认预算 15 分钟，可选 3 或 30 分钟；每个 Agent 可重复 1、3、5 次。预算包括 Agent 启动和工具循环，排队、环境准备、正式验收分别处理。每次最多 160 个工具调用；公开测试和验收有独立超时。
- 提交后关闭 Agent 和工作容器，在全新基线应用允许的文件修改。验收目录由 root 持有并只读，候选代码仍以非 root 运行；公开回归、Node 语法检查、全部固定验收条件共同决定是否交付通过。`node --check` 不等同于 TypeScript 类型检查。
- 所有结果保留补丁、提交源码、日志、协议和工具轨迹，附 SHA-256；刷新读取完整状态快照。取消后关闭会话和容器，迟到输出不能进入记录；重启将未完成实验标记中断，不自动重新消费模型额度，并尝试清理该记录持有的容器。
- 首版仅支持这些小型固定 Node/TypeScript 仓库。尚不支持任意真实仓库导入、安装依赖、浏览器项目构建、联网工具、工程 LLM 代码质量评分，亦不声称是对恶意程序的完整安全认证。验收覆盖明确功能边界，仍需持续扩充反作弊与资源故障测试。

工程工具使用 MCP Streamable HTTP 的本机端点和每次试验独立的临时认证；执行器配置仅批准这四个受限工具。[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)、[Codex MCP 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

## 科学口径修正

- 任务指纹、裁判身份、工具版本、执行预算或任务累计预算变化时拒绝严格同卷回归。旧记录缺少指纹时拒比；有指纹但缺少执行信息时明确标为描述性对比。
- 题目诊断按实验协议分组，避免编辑题目后相同题号混合旧新观测。CLI 可用 `analyze <题库> --protocol <分组>`；网页可直接选择分组。
- 单个观测不再显示退化的置信区间；零方差裁判的相关系数标为不可定义，同时保留平均绝对分歧。相关性、排名协调程度和内部一致性不再作为总体能力可信的证明。
- 工程结果展示计划试验数、实际开始数、环境有效数、通过次数、失败类型及耗时，保留失败分母。不同环境或验收器不混合比较；实验协议还保存执行器源码摘要。
- 原生 Agent 的比较测量整个 Agent 系统。实际底层模型和供应商采样参数没有由当前桥接协议完整返回，按未知披露。重复运行同一个开发任务不等于多个独立任务，结果页不会宣布模型总体能力显著更强。
