## 0. 结论速览（TL;DR）

1. **模型 id 无法可靠判定「免费档」**。`openrouter:*:free` 可靠；但**本机 9 个免费渠道全部是 `custom:<uuid>`**，免费性质只写在**显示名**里（"Groq 免费档"、"B.AI 活动免费"），id 完全无法区分。→ **这是本设计的核心约束**。
2. **免费档是一个「启动方式」而非「模型属性」**：网页/3D 通过 URL 参数 `freeOnly=1` 声明（`battle-engine.ts:260`），但**这个参数从未被写进战绩 JSON**（今日 v3.35 的免费 bracket 战绩 `meta` 里没有任何档位痕迹，见 §1.2）。→ 想在读侧分组，**必须有启动期落盘的一个标记**。
3. **`meta.source` 就是现成的分组键**：v3.34.4 的 `game-duel` 机制已经证明「来源标记 + 单独成组 + 不入积分」这条路走得通（`types.ts:199`、`analyze.ts:130`、`experiment-protocol.ts:14`）。**复用它是本稿推荐方案**。
4. **拦截层选在生涯结算边界 `career-store.ts:51 settleBattle()`**——它是 `career.json` 的唯一写入点，所有调用方（网页、CLI、淘汰赛、评分重试）都从这里过。在此早退 → 免费档**根本不产生生涯条目** → 主榜（CLI `stable` / 网页 / 桌面 API）**天然看不到**，无需逐个榜单改造。
5. **schema 只需动 1 个可选字段**（`meta.source` 的联合类型加一个成员），**不需要迁移、不需要动 `career.json` 结构**。
6. **旧战绩沿用 `quality-efficiency-v1` 先例**（`performance.ts:10`："按当时规则展示，不重算"）：现有 4 条免费参赛记录（1 场 v3.8.0 战绩，4 只 `openrouter:*:free` 各 1 场生涯）**保持原样**，新规则只管新增。
7. ⚠️ **最大风险**：**3D 客户端两条对战路径都被硬编码为「只走 OpenRouter 免费档」**（`game-api.ts:234`、`game-competition.ts:505,528`）。也就是说**目前 3D 根本无法产出 BYOK 正式档数据**。用户设想的「BYOK 升为对外拍摄唯一入口」在 3D 侧**需要额外工程**，不属于最小改动集。

## 1. 现状结论（7 项探查）

### 1.1 模型来源如何表示？能否从 id 可靠判定「免费档」？

**结论：不能。** id 只能判 `openrouter:*:free` 与 `mock:`，`custom:` 一律判不出。

| 来源 | id 形态 | 解析位置 | 能否判免费 |
| --- | --- | --- | --- |
| 内置 mock | `mock:xueba-o9` | `models.ts:46-55` `resolveContestant` | 不是「免费」，是**离线演示**（`mock.ts`） |
| 本机 Agent | `agent:codex/...` | `models.ts:42-45` | 不适用 |
| OpenRouter 免费目录 | `openrouter:<org>/<model>:free` | `models.ts:261-284`；目录见 `openrouter.ts:25-53` | ✅ **可靠**：目录按「全部计价字段 == 0」筛选（`openrouter.ts:37`），开赛前 `requireFree()` 复核（`:92-98`），请求再叠加零价上限（`models.ts:279`） |
| 自定义直连端点 | `custom:<uuid>` | `model-settings.ts:12-19`、`models.ts:263-267` | ❌ **不可判**：id 是随机 UUID；`CustomModel` 里没有 free/tier 字段 |
| DOTS 直连 | `dots:dots3-note-prev` | `models.ts:103-105` `CUSTOM_ENDPOINTS` | ❌ 端点存在但不带免费语义 |
| 其它 pi-ai 内置 | `deepseek:...` / `kimi-coding:...` | `models.ts:286-291` | ❌ 取决于用户 Key，非「免费档」概念 |

**关键实证**：本机 `.local/model-settings.json` 里 9 个免费渠道全部是 `custom:`，免费性质**只在 `name` 字段的人话里**：

```
custom:670c810a… | name "Qwen3.8-Flash · B.AI 活动免费" | modelId qwen3.8-flash             | baseUrl https://api.b.ai/v1
custom:68bfc401… | name "GLM-4.7-Flash · 智谱"         | modelId glm-4.7-flash             | baseUrl https://open.bigmodel.cn/api/paas/v4
custom:06b844ac… | name "Qwen3.5-4B · 硅基流动"        | modelId Qwen/Qwen3.5-4B           | baseUrl https://api.siliconflow.cn/v1
```

（来源：`docs/多渠道免费模型接入-2026-09-13.md:5-16`；本机 `.local/model-settings.json` 实读，未打印密钥。）

**`model-labels.ts` 也不含免费位**：它只把 `(modelId, provider, baseUrl)` 映射成 `{manufacturer, channel}`（`model-labels.ts:29-58`），**没有 free/tier 字段**。

**唯一带 `free` 布尔的地方是 HTTP 响应，不是持久层**：`model-api.ts:42`（目录模型 `free:true`）、`:46`（`custom` 一律 `free:false`）、`:47`（builtin `free:false`）。→ 前端拿得到，但**不落盘**。

> ⚠️ 顺带一条口径不一致：`custom:` 免费渠道在 `/api/models` 被标 `free:false`（`model-api.ts:46`），而 3D 客户端据此渲染 `ArenaDuelController.cs:292` 的计费标签 → **免费渠道在 3D 里被显示成「API 计费」**。这既是 UI 瑕疵，也说明「免费性」目前没有单一事实来源。

### 1.2 战绩 JSON 的 schema：有没有可用来分组的字段？历史文件里有没有标记？

**结论：有现成字段 `meta.source`，但历史上从未有文件用过它；今日的免费战绩也没有任何档位标记。**

- 战绩结构：`types.ts:171-201` `BattleResult`，其中 `meta`（`:182-200`）含 `arenaFingerprint / judgeModels / toolVersion / plannedTasks / rankingPolicy / judge / taskBudgetMs / execution / source?`。
- `source` 的定义与注释（**就是本需求要复用的字段**）：
  ```ts
  // types.ts:198-199
  /** 数据来源：3D 对决的答卷单独成组，不与网页批量评测混算 */
  source?: 'game-duel';
  ```
- 落盘位置与命名：`results-store.ts:16-21` `saveBattle()` → `results/战绩-<arena>-<stamp>.json`；毫秒精度。
- **实测 181 个战绩文件**（`arena/results/战绩-*.json`）：
  - `meta.source`：**181/181 为 undefined**（无任何文件用过）。
  - 参赛 id 分布：`mock:*` 约 176 次/只；`dots:*` 7；`custom:*` 6；`deepseek:*`/`kimi-coding:*` 各 2；`openrouter:*:free` 共 4 只。
  - **只有 1 个文件含 `openrouter:*:free`**：`战绩-syllogism-2026-09-10T16-03-41-288.json`（toolVersion 3.8.0，4 只全免费）。
- **今日（2026-09-23）核验产物**：`docs/validation/_ququ-results-2026-09-23/战绩-dyck-bracket-2026-09-23T05-12-45-673.json`
  - `rankingPolicy: quality-ci-v1`、`toolVersion: 3.35.0`、`meta` 键 = `[arenaFingerprint, judgeModels, toolVersion, plannedTasks, rankingPolicy, execution]`
  - 参赛：`openrouter:nvidia/nemotron-3-super-120b-a12b:free`、`openrouter:nex-agi/nex-n2.5-pro:free`
  - **`source` 不存在** → 免费档的事实**在落盘时丢失**。这正是必须新增启动期标记的直接证据。

### 1.3 榜单与积分口径：「不进主榜」要在哪一层拦？

**主榜 = `career.json` 的 Glicko 严格排序视图**，链路如下：

```
settleBattle(career-store.ts:51)  ← career.json 唯一写入点
   └─ settleOnBook(career.ts:109)  ← 纯函数：算 elo / titles / glicko
        └─ gamesFromBoard(glicko.ts:119) + glickoUpdate(glicko.ts:83)

stableView(career.ts:285)  ← 生涯总榜视图（排序依据 r − 2·RD）
   ├─ CLI  stable   : commands-battle.ts:201-238（无过滤）
   ├─ 网页 总榜页   : stableHtml.ts:33（web=true 时滤掉 mock:）
   ├─ 网页 首页 Top5: server.ts:124-127（滤掉 mock:）
   └─ 桌面 API /rankings : desktop-api.ts:93-95（滤掉 mock:）
```

- **积分**（字段名仍叫 `elo`，已更名「积分」）：`career.ts:35` 定义，`career.ts:153` `entry.elo = after`；语义见 `career.ts:282-284`（逐场累加、无界增长，**只驱动段位，不作排序**）。
- **主榜排序**：v3.34.4 起改为 **Glicko 保守估计 `r − 2·RD`**，见 `glicko.ts:145-147`、`career.ts:310,316`。`RD > 200` 标「暂定」（`glicko.ts:142,149`）。
- **单场名次/夺冠**：`leaderboard.ts:37 buildLeaderboard()`，排序键见 `:68-74`（弃权沉底、NaN 沉底、`avg` 降序、`elo` 兜底）。
- **CLI 出榜**：`node src/cli.ts stable` → `cmdStable`（`commands-battle.ts:201`）。

**「不进主榜」的候选拦截层对比**：

| 层 | 位置 | 能否满足「不进积分 + 不进任何榜」 | 代价 |
| --- | --- | --- | --- |
| **结算写层**（推荐） | `career-store.ts:57-63` 之前早退 | ✅ 根本不产生生涯条目 → 4 个读榜点自动干净 | 免费档没有「生涯历史」，但战绩 JSON 仍在 |
| 读侧过滤 | `career.ts:285 stableView` | ⚠️ 要改 1 处核心 + 语义上条目仍写进 `career.json`（污染账本，重蹈 mock 覆辙：mock 有 1859 场在册、只在网页被滤掉） | 中等 |
| 结果目录隔离 | 新的 `results/demo/` | ✅ 物理隔离 | 大：`results-store`/`analyze`/`diff`/`recap`/`latestBattleFile` 全要感知子目录 |

→ **推荐第 1 层**：免费档在 `settleBattle` 直接早退，`career.json` **一行不写**。

### 1.4 已有先例（设计模板）：`game-duel` 来源分组 + 不入积分

**这套机制确实存在，且和本需求高度同构，应当复用而非另发明。**

- **落盘在独立 store**：3D 对决存 `results/game-competitions/c*.json`（`analyze.ts:85`、`game-competition.ts:159` 注释明示 *"Durable game state is separate from benchmark rankings and career settlement."*）。
- **结算侧完全不入积分**：`game-competition.ts` 全文**从不调用 `settleBattle`**；只 `loadCareer` 读来当种子（`game-competition.ts:241-242`）。
- **回流研究时才合成 BattleResult 并打来源标记**：`analyze.ts:84-144 gameDuelResults()`，其中
  ```ts
  // analyze.ts:126-138
  meta: { arenaFingerprint: fingerprint, judgeModels: [...], toolVersion: ARENA_VERSION,
          source: 'game-duel', execution: {...} }
  ```
- **来源进入协议键 → 自动单独成组**：`experiment-protocol.ts:13-14`
  ```ts
  // 只在有来源标记时加入：历史记录的协议键保持不变
  ...(result.meta?.source ? { source: result.meta.source } : {}),
  ```
  再来 `protocolKey`（`:38-50`）→ `analyze` 按协议分组（`analyze.ts:158-163`），混合时要求 `--protocol` 选组。
- **CLI 入口**：`analyze <罐> --include-game`（`commands-pipeline.ts:176-183`）。

**可复用点**：`meta.source` 这条「来源键 + 协议分组」的现成管道。**不可直接照搬点**：free 档不像 3D 对决那样有独立 store，free 档走的是正常 `battle-engine` 主链路（仍会 `saveBattle` + `settleBattle`，`battle-engine.ts:567-568`），所以必须在**结算边界加一道闸**。

### 1.5 旧战绩处理先例：`quality-efficiency-v1` → 「按当时规则展示，不重算」

**这是分层降级处理旧档的现成范式。**

- 常量与注释：`performance.ts:9-15`
  ```ts
  export const RANKING_POLICY = 'quality-ci-v1' as const;
  ```

  - `report.ts:41-42`、`report.ts:352-353`（`efficiencyRanked` 决定战报口径）
  - `commentary.ts:30`（解说词口径）

- 对外表述：`CHANGELOG.md:25`「旧战绩（`quality-efficiency-v1`，综合分定名次）**按当时规则展示，不重算**」。

→ **分层降级的旧档策略应完全沿用此范式**：不批量改历史战绩 JSON、不动 `career.json`、**新规则只对新增战绩生效**。

## 2. 推荐设计

### 2.1 核心决定

| 决定项 | 结论 | 理由 |
| --- | --- | --- |
| **档位在何时判定** | **启动期判定，落盘到 `meta.source`** | id 判不出（§1.1）；`freeOnly` 是启动参数且当前不落盘（§1.2） |
| **分组落地方式** | **复用 `game-duel` 的 `meta.source` 渠道**，新增取值 `'free-tier'` | 现成管道，改动最小；`experiment-protocol.ts:14` 会自动把它分到独立协议组 |
| **拦截层** | **`career-store.ts:51 settleBattle()` 内早退** | `career.json` 唯一写入点，覆盖全部调用方（§1.3） |
| **schema 动不动** | **只动 1 个可选联合类型**（`types.ts:199` 加成员），**不动 `career.json`、不做迁移** | 满足「能不动 schema 就不动」的精神——仅扩枚举，不加字段 |
| **旧战绩** | **不动、不重算**，沿用 `quality-efficiency-v1` 先例 | §1.5 |

### 2.2 推荐落地（最小形态）

1. **启动期打标**：`runBattle` 生成 `meta` 时（`runner.ts:482-497`）写入
   `...(档位 === 'demo' ? { source: 'free-tier' as const } : {})`。
   档位来源：`battle-engine.ts:260` 的 `openRouterFreeOnly`（网页/3D 免费入口 = demo；CLI = official）。
2. **结算期拦截**：`career-store.ts` 的 `settleBattle()` 增加一条早退条件
   （放在现有 `:57-63` 的早退判断里）：
   ```ts
   result.meta?.source === 'free-tier'   // 演示档不结算生涯、不进积分、不进任何榜
   ```
3. **读侧零改动**：`stableView` / CLI / 网页 / 桌面 API **一行都不用改**——因为根本没有条目产生。
4. **研究侧自动分组**：免费档战绩作为独立协议组出现在 `analyze`（无 `--protocol` 时会要求选组），与正式档不混算。

### 2.3 关于「档位判定规则」的诚实说明（**需用户拍板**）

最小形态把「档位」等价于「是否用了免费入口（`freeOnly=1`）」。这能覆盖：

- ✅ 网页免费目录选模型开赛（`modelPickerHtml.ts:2`）
- ✅ 3D 客户端对战（`game-api.ts:234` 硬编码 `freeOnly=1`）
- ✅ 3D 淘汰赛（`game-competition.ts:505,528`）

**但它覆盖不了**：用户把 `custom:` 免费渠道（Groq 免费档 / B.AI 活动免费 / 智谱免费 / 硅基流动免费）**当作普通自定义模型、在非 `freeOnly` 路径开赛**的情况——这些仍会进正式榜。这与发布红线 **R2-3**（`docs/发布/投稿规格-B站.md:252`：不得用中转/免费渠道的一次响应代表厂商官方水平）**直接冲突**。

→ 两种收口（**待用户选**）：
- **(甲) 接受已知泄漏**：只把「走免费目录/演示入口」的场次算演示档；`custom:` 免费渠道靠**人工自律**（发布时按 R2-3 标注渠道）。改动最小。
- **(乙) 显式档位**：在阵容/开赛层加「演示档/正式档」开关（可默认：阵容含 `mock:`/`openrouter:*:free`/已知免费渠道 → demo），把免费性质**变成数据结构**，兑现「R2-3 从文案自律升级为数据结构保证」。改动更大（见 §3.2 完整版）。

### 2.4 旧战绩怎么办

**完全沿用 §1.5 范式：不迁移、不重算、按当时规则展示。** 具体：

- 现有 1 场含 `openrouter:*:free` 的旧战绩（`战绩-syllogism-2026-09-10T16-03-41-288.json`，v3.8.0）**保持原样**。
- `career.json` 里已有的 4 条免费模型生涯条目（各 1 场）**不删除**——`quality-efficiency-v1` 先例就是「不改写历史存档」。
- 新规则**只对新增战绩生效**（打新标 → 不进结算）。
- **不改 `career.json`**（硬约束，且符合范式）。

## 4. 最小改动集的定义与「够不够支撑拍摄」

**最小改动集的定义**：达成 (a) **免费档战绩不再进入 `career.json`（→ 不进积分、不进主榜、不进网页/桌面/CLI 任何榜）**，且 (b) **明天开拍不被阻塞** 所需的最少改动 = §3.1 的 4 文件 ~15 行。

**它够不够支撑拍摄？——分两说，必须讲清：**

- ✅ **对「把免费档挡在主榜外」——够**。拦截在唯一写入口，是结构性保证，不依赖任何读侧自律。
- ✅ **对「用网页后台 + BYOK 正式模型拍摄」——够**。网页 `/battle` 不带 `freeOnly` 即走正式档，走主链路结算进主榜，**无需任何额外改动**。
- ❌ **对「用 3D 客户端拍摄 BYOK 正式档」——不够**。3D 两条路径当前**硬编码免费档**（`game-api.ts:234`、`game-competition.ts:505,528`），去掉这个硬编码属于完整版 C 项。**若「对外拍摄」依赖 3D 客户端，则最小集不成立，必须并入 C 项一起排期。**

> 一句话：**最小集能保证「免费档脏数据不进榜」，但不能保证「正式档能从 3D 拍出来」。这一点请在排期前先与用户确认拍摄载体。**

## 6. 不做什么（本次明确不在范围）

以下三项**是否纳入分层降级由设计论证，但一律不要实现**（本次亦未实现）：

其它不在范围：

4. 不删 `free` 徽章 / 免费筛选 / 零价核验等**免费专属功能**。
5. 不做任何**战绩 JSON 批量改写**或 `career.json` 迁移。
6. 不改网页后台、3D 客户端的**任何代码**（本稿对 UI 仅作盘点，见 §1.7）。
