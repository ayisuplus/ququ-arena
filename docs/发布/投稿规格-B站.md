# B 站投稿规格与发布清单 · AI斗兽场 QuQuArena

> 面向：拍完一条真实多模型对决视频之后，到稿件发出去、第一批反馈收回来。
> 适用版本：arena v3.35.0（`quality-ci-v1` 科学口径）、3D 客户端 v26（`BuildProduction`）。
> 本文只规定**发布与运营层面**的规格与门控，不涉及代码改动。

---

## 0. 怎么用这份文档（先读这段）

**执行顺序**：§4 发布检查清单 → §2 标题简介 → §1 规格 → §3 红线复核 → 投稿 → §5 冷启动。
**不要跳过的两步**：§3 红线清单（防止为了流量牺牲诚实）、§4 的 G2 脱敏（防止 Key / 本机路径泄露）。

**一个必须知道的前提变更**：v3.18 曾交付「投稿素材卡」（标题×3+简介+标签一键复制），但 **v3.34.4 已随「网页收敛为后台 + 研究台」移除**，观赛演出整体迁到 3D 客户端。
也就是说：本轮**没有自动生成文案的工具了**，标题与简介必须按 §2 手工填。
而且——**旧素材卡的文案模板不能照抄**：它无条件输出「XX 夺冠」，在 v3.35 的口径下，如果本场 CI 含 0（inconclusive），那样写就是造假。这是 §3 的第一条红线。

**口径速查卡（写任何对外文案前先对一遍）**

| 项目 | 正确表述 | 错误表述 |
|---|---|---|
| 名次依据 | 只按**答题均分** | 按速度 / Token / 缓存 / 综合分 |
| 判「胜者」的条件 | 第一名与第二名的**配对 bootstrap 分差 95% CI 不含 0** | 均分高一点就算赢 |
| CI 含 0 时 | 结局是 `inconclusive`，只能写**「暂列第一」**、**「差距在统计误差内」** | 「夺冠」「击败」「战胜」「赢了」 |
| 速度 / Token / 缓存 | **效率参考，不决定名次**（可作为看点，需明示不影响名次） | 「又快又准所以第一」 |
| 弃权（调用失败/429/重试耗尽） | 与答错**严格分离**，不进任何分数计算，必须单独说明数量与原因 | 当 0 分算进均分、说成「不会做」 |
| 题库指纹 | sha256（规范化 judge 规则 + 全部题目），引用战绩必须带上 | 只说「用了我们的题」 |

## 1. 投稿规格（B 站）

### 1.1 视频文件规格

> ⚠️ **本节数值来自公开第三方汇总与历史投稿页信息，平台规则会变**。
> 凡标「待核实」的，**投稿前以创作中心投稿页的实时提示为准**（见 §1.6 核实路径）。
> 本节给出的是「照着做不会踩坑」的工程取值，不是官方承诺值。

| 项 | 建议取值 | 状态 | 说明 / 为什么这么定 |
|---|---|---|---|
| 封装格式 | **MP4** | 可靠 | MP4/flv 是官方推荐格式，转码更快、审核更快。3D 客户端录完若为 mkv/mov，先封装成 MP4（不重编码可加 `-c copy`） |
| 视频编码 | **H.264 / AVC** | 可靠 | 兼容性最好。H.265/AV1 在部分链路会二次压制 |
| 分辨率 | 录制 **1920×1080（16:9）**；若录 2K/4K，成片仍建议导出 1080p | 部分待核实 | 1080p 是长期稳妥档；更高分辨率是否免二次压制**待核实** |
| 帧率 | **与录制一致，不重采样**（推荐 30fps；录到 60fps 就按 60fps 交） | 可靠 | 改帧率会让 3D 动画出现抖动/重影 |
| 视频码率 | 1080p30 取 **8–16 Mbps** 交源文件；平台侧上限**待核实**（历史口径 6000 kbps / 峰值 24000 kbps） | **待核实** | 高码率源文件在平台二次压制后观感更好；**不要**为了压到 6000 以下而损伤画面。以投稿页提示为准 |
| 音频编码 | **AAC**，48 kHz 或 44.1 kHz，立体声，192–320 kbps | 可靠 | 历史口径采样率 44100、≤2 声道、≤320 kbps |
| 关键帧间隔 | **≤10 秒**（建议 2 秒） | 可靠 | 历史口径「平均至少 10 秒一个关键帧」；GOP 太长会影响拖动与压制 |
| 扫描方式 | **逐行扫描**（非隔行） | 可靠 | 隔行会被二次压制 |
| 色彩空间 / 位深 | yuv420 / 8bit | 可靠（历史口径） | 10bit / 444 是否被接受**待核实** |
| 文件大小 | 单文件上限**待核实**（历史口径普通用户 4GB、大会员 8–20GB 说法不一） | **待核实** | 按 1080p / 12 分钟 / 12 Mbps 估算约 1 GB，正常不会撞线 |
| 时长 | 见 §1.5 | — | — |

### 1.2 封面

| 项 | 建议取值 | 状态 |
|---|---|---|
| 格式 | JPG 或 PNG | 可靠 |
| 尺寸 | **≥1146×717**，按 16:9；直接做 **1920×1080** 最省事 | 建议值，最低门槛（历史为 ≥960×600）**待核实** |
| 文件大小 | ≤5 MB | 可靠 |
| 动图 | **不可用**动态图 | 可靠 |
| 内容 | 必须是**视频内容截图或与视频主体一致**；不得含钱币/国旗/政治等禁发元素 | 可靠 |

**本项目的封面硬要求（比平台更严）**

1. **封面文字必须和赛果口径一致**。CI 含 0 时封面**不许出现「冠军」「夺冠」「战胜」「完胜」**，只可写「暂列第一」或「差距在误差内」。
2. **封面不许出现具体模型厂商 Logo**（授权与商标风险），只用项目自绘的蛐蛐形象 + 模型显示名文字。
3. 封面文字**不写在最下方**（会被播放量/时长白字遮挡）。
4. 封面上的**分数必须与战报一致**，且保留两位有效位（如 78.3%），不四舍五入成整数制造差距感。

### 1.3 标题 / 简介 / 标签 / 分区

| 项 | 建议取值 | 状态 |
|---|---|---|
| 标题长度 | **≤80 字符**（投稿页历史显示 `18/80`）；实践建议 **24–34 个汉字**，前 12 字放核心看点 | 上限值**待核实**，以投稿页实时计数为准 |
| 标题语言 | 尽量中文；模型名等专有名词用官方形式 | 可靠 |
| 标题禁用 | 画质/音质测试字样；无意义/与内容无关/挑衅引战标题（如「第一次投稿求支持」「点开你会回来转的」） | 可靠 |
| 简介长度 | 历史投稿页曾显示 `0/250`，另有 2000 字说法 —— **冲突，待核实** | **待核实**；按 §2.4 的骨架写，若超 250 则压缩到 4 段以内 |
| 标签数量 | **最多 10 个**；建议用满 6–10 个 | 上限**待核实**（多数来源为 10） |
| 标签规则 | 与内容直接相关；每个标签长度上限（历史 12 汉字）**待核实**；禁止堆砌无关热词 | 可靠 + 上限待核实 |
| 分区 | 主推 **科技数码 → 计算机技术**；备选 **知识 → 科技科普** | **待核实**：以投稿页实际可选分区名为准，别硬套 |
| 稿件类型 | **自制**（原创录制 + 原创工具） | 可靠 |

### 1.4 合规开关（投稿页「更多设置」）

| 开关 | 建议 | 说明 |
|---|---|---|
| 声明原创 / 自制 | ✅ 勾选 | 我们是原创录制 + 自研工具 |
| **AI 生成内容标识** | ✅ **建议勾选** | 本视频的**解说文本由 AI（默认 Pi / 可选 API 模型 / 本地 Agent）生成**，赛后文案也可能经 AI 润色。B 站对 AI 生成内容有标识要求，**具体触发条件与开关名称待核实**（投稿页「更多设置」查看）。**宁可多标一次，不要漏标** |
| 转载授权 | 建议**允许转载**（冷启动期扩散优先） | 见 §5.2 决策 |
| 弹幕 / 评论 | 全开 | 冷启动期要的就是互动 |
| 定时发布 | 见 §5.2 首发布点建议 |  |
| 合集 | 建「AI斗兽场·多模型对决」合集，本条为第 1 期 | 便于后续系列沉淀 |

### 1.5 时长策略（我们自己的建议，非平台约束）

| 版本 | 时长 | 用途 |
|---|---|---|
| **主片** | **8–12 分钟** | 完整一场：入场报幕 → 逐题对抗 → 颁奖/暂列第一 → 赛后数据解读。B 站知识/技术类内容有完整叙事的容忍度 |
| **切片（1–3 条）** | **60–120 秒** | 高光时刻（团灭题 / 翻盘 / 解说金句），首发同期或次日放出，用于引流 |
| 竖屏短版 | 30–60 秒 | 仅当平台竖屏入口可用时做，规则**待核实** |

**节奏硬要求**：开场 **15 秒内**必须说清「这场在测什么能力、哪几个模型、赌注是什么」。3D 客户端的入场报幕可以承担这个作用，但**不要用纯演出开场**——冷启动期观众不认识这个项目。

### 1.6 待核实清单与核实路径（投稿前逐条过一遍）

| # | 待核实项 | 去哪核实（按顺序） |
|---|---|---|
| N1 | 视频码率上限 / 峰值码率 | 创作中心 → 投稿页上传后的提示；B 站帮助中心「投稿指南」 |
| N2 | 分辨率上限（是否支持 4K 免二压） | 同上；或先用 1080p 投稿观察是否提示「二次压制」 |
| N3 | 单文件大小上限 | 投稿页选择文件时若超限会直接报错 |
| N4 | 简介字数上限（250 还是 2000） | 投稿页简介框右下角实时计数 |
| N5 | 标题字符上限（80 字符 / 30 字） | 投稿页标题框实时计数 |
| N6 | 标签数量与单标签长度上限 | 投稿页标签输入区提示 |
| N7 | 封面最低尺寸与格式大小限制 | 投稿页封面上传弹窗内标注 |
| N8 | AI 生成内容标识的触发条件与开关位置 | 投稿页「更多设置」；B 站公告/《创作公约》 |
| N9 | 准确的分区名称与层级 | 投稿页分区下拉（**以实际可选项为准**） |
| N10 | 竖屏/短视频入口与规则 | 创作中心首页入口是否存在 |

> **核实原则**：投稿页的实时提示 > 帮助中心文档 > 第三方教程。第三方教程的数字互相打架（本次检索到的同一项指标有 3 种以上说法），**不要拿它们当依据**，只用来预判。

## 2. 标题与简介策略

### 2.0 通用命名规则

- **固定前缀**：`【AI斗兽场】` —— 建立系列识别度，也占住搜索词。
- **禁止**：在标题里写死「夺冠 / 击败 / 战胜 / 碾压」——除非 §4 G3 已确认本场 CI 不含 0。
- **分数写法**：`78.3%`，保留一位小数；**禁止**为了戏剧性写成「八成」或凑整。
- **模型名**：用配置里的**显示名**，不用内部 ID；不同渠道的同名模型必须带渠道标注（见 §3 R2-3）。

### 2.1 模板 A · 碾压局（CI 不含 0，可判胜者）

**适用**：第一名与第二名的配对 bootstrap 分差 95% CI **不含 0**，系统判定「胜者」。

```
【AI斗兽场】{{N}}个大模型同考{{罐名}}，{{冠军}} {{均分}} 领先第二名 {{分差}} 个百分点
【AI斗兽场】{{罐名}}：{{冠军}} {{均分}}，把{{垫底}}（{{垫底分}}）甩开{{分差}}——差距在误差之外
【AI斗兽场】{{团灭题号}} 一题放倒{{X}}个模型：{{罐名}}到底在考什么
```

**为什么能这么写**：CI 不含 0 是「统计显著」的硬证据，可以说「领先」。但仍**建议写「领先 X 个百分点」而不是「碾压」**——误差之外的差距也可能是 3 个百分点，"碾压"是修辞不是事实。

### 2.2 模板 B · 神仙打架 / inconclusive（CI 含 0）——**最容易写错的一套**

**适用**：CI **含 0**，结局 `inconclusive`。3D 客户端此时**不演颁奖、不演败北**，屏幕提示「暂列第一（差距在统计误差内）」。

```
【AI斗兽场】{{N}}个大模型考{{罐名}}，{{第一名}} {{均分}} 暂列第一——但差距在统计误差内
【AI斗兽场】{{第一名}} {{均分}} vs {{第二名}} {{第二分}}：这场没法判赢家，数据说了为什么
【AI斗兽场】我们给了{{N}}个模型{{题数}}道题，结果没能分出高下——这本身才是有意思的部分
```

**强制动作（三选一必做）**：
1. 标题或封面**至少一处**出现「暂列第一」「差距在误差内」「没能分出高下」这类措辞；
2. 简介第一段必须写明 CI 区间与「含 0」；
3. 视频内**必须保留** 3D 客户端的「暂列第一（差距在统计误差内）」画面，**不得剪掉或替换成颁奖动画**。

> 第三点是硬约束：如果画面是「暂列第一」而标题是「夺冠」，观众会立刻发现文案与画面对不上。**这是本项目最典型的翻车方式。**

### 2.3 模板 C · 大爆冷

**适用**：赛前赔率（Glicko 种子/预期胜率）与实际名次显著背离，或某道题出现大面积团灭。

```
【AI斗兽场】赛前最不被看好的{{冷门}}，在{{罐名}}上拿了{{均分}}
【AI斗兽场】{{题号}} 团灭：{{X}}/{{N}} 个模型在这道题上全部失手
【AI斗兽场】{{强队}} 翻车了——{{罐名}}上它只拿到{{均分}}，问题出在第{{题号}}题
```

**注意**：「爆冷」是相对**赛前预期**的描述，不是对模型能力的定性。写的时候要把「赛前预期来源（Glicko 保守估计 / 历史战绩）」说清楚，否则就是把一次抽签结果说成能力结论（§3 R2-2）。

### 2.4 简介模板

**通用骨架（4 段，按顺序）**

```
【这场在测什么】
{{罐名}}（{{题数}}题）：{{一句话说明测的是哪种能力，例：多步算术中的诚实度——题面里放了诱饵答案}}。
题库指纹 sha256:{{指纹16位}} · canary: ququ-arena:{{...}} · 裁判: {{judge列表}}

【参赛阵容】
{{N}} 只蛐蛐：{{逐只列出 显示名（渠道）+ 均分 + 95%CI + 弃权数}}
速度 / Token / 缓存只作效率参考，不参与名次。

【赛果】
{{按 §0 口径卡选择表述}}
· CI 不含 0：{{冠军}} 以 {{均分}} 领先第二名 {{分差}} 个百分点，配对 bootstrap 95% CI 为 [{{lo}}%, {{hi}}%]，不含 0，判胜者。
· CI 含 0 ：{{第一名}} {{均分}} 暂列第一，与 {{第二名}}（{{第二分}}）的分差 95% CI 为 [{{lo}}%, {{hi}}%]，**包含 0——差距在统计噪声范围内，名次不足以下强结论**。

【数据可核（不是"可复现"的过度承诺，见下）】
本场战绩 JSON + 战报 HTML 已随视频附件放出（{{链接}}），内含：题库指纹、逐题答卷、裁判给分与分歧度、CI 计算参数（B=2000，种子 42）。
重跑需要自备 API Key 与题库包（{{获取方式}}）；**在相同题库指纹下**，同一战绩文件重渲染出的 CI 完全一致。

【关于这条视频】
录制：QuQuArena3D 客户端观赛 + 屏幕录制，赛况与分数均为实时真实数据，未做后期替换。
解说文本由 AI 生成（{{来源}}），已按平台规则标识。
本项目不卖模型、不接厂商推广；任何模型名称均为公开产品名，本场结果只代表在本题库本次调用下的表现。
```

**「数据可复现」声明的三档写法（按你能交付到哪一档，就写哪一档，不许越档）**

| 档 | 你能交付 | 可以写 | **不能写** |
|---|---|---|---|
| **L1 · 可核** | 只放战绩 JSON + 战报 HTML | 「赛果数据可核：指纹、逐题答卷、CI 参数全部随附件公开」 | 「任何人都能复现」「一键复现」 |
| **L2 · 可重渲染** | 附件**含题库包 + judge 规则**，他人装本工具后可对同一战绩文件重跑渲染 | 「同一战绩文件在相同指纹下可重渲染，CI 逐位一致」 | 「榜单可复现」（没跑过就不能说） |
| **L3 · 可重跑** | 附件含**题库包 + 工具 + 运行说明**，他人自备 Key 可完整重跑 | 「自备 API Key 后可完整重跑；结果受模型版本与采样影响，不保证逐题一致」 | 「结果稳定可复现」（LLM 采样本身有波动，且方法学 §5 已明示裁判温度未固定） |

> **当前默认按 L1 准备**，能凑齐 L2/L3 再升级措辞。项目目前：**sites 仓库冻结、serve 默认只监听 127.0.0.1、无公开 git remote** —— 所以在没有交付物之前写「可复现」是**空头承诺**，属于 §3 R1-4。

### 2.5 标签（建议 8 个，≤10）

```
AI斗兽场（主标签）· 大模型 · LLM评测 · benchmark · 电子斗蛐蛐 · 人工智能 · 科技 · {{罐能力关键词}}
```

- 主标签固定 `AI斗兽场`，建立品牌搜索。
- `{{罐能力关键词}}` 按本场罐的能力填（例：诚实度 / 多步推理 / 指令遵循）。
- **禁止**：塞与本场无关的当红模型名当流量标签；塞「AI绘画」「ChatGPT 教程」等无关热词。

### 2.6 封面文案与标题一致性

封面上的**每一个数字和结论都必须能在简介里找到出处**，且**与视频画面一致**。
建议封面只放三样：`【AI斗兽场】` + 罐名 + 一个分数/一句结论。信息越少越不容易出错。

## 3. 内容红线清单（对外文案绝不能怎么写）

> 这条清单的价值：**防止为了流量牺牲诚实**。本项目的人设就是「宁可说差距在统计误差内」，砸了这个人设，这条视频的长期价值归零。
> 用法：文案定稿后，逐条对照打勾；**任一条 R1 未通过 = 不许投稿**。

### R1 · 硬红线（触碰即为事实错误 / 造假）

| # | 绝不能这么写 | 为什么 | 正确写法 |
|---|---|---|---|
| **R1-1** | 把 `inconclusive`（CI 含 0）写成「夺冠 / 击败 / 战胜 / 赢了 / 冠军是 X」 | v3.35 口径：CI 含 0 时**没有胜者**，只有「暂列第一」；3D 客户端也不演颁奖 | 「{{第一名}} {{均分}} 暂列第一，与 {{第二名}} 差距在统计误差内（95% CI [lo, hi]，含 0）」 |
| **R1-2** | 用速度 / Token / 缓存 / Elo / 积分来解释名次 | 名次只按答题均分；其余是效率参考或跨场积累，与单场名次无关 | 单独列为「效率参考（不决定名次）」板块 |
| **R1-3** | 把 429 / 配额 / 调用失败导致的**空答案（弃权）**说成「模型不会做」「答不上来」「翻车」 | 弃权与答错**严格分离**，不进任何分数计算；把限流说成能力是双重造假（既冤枉模型，又虚增了样本） | 「本场 {{X}} 次弃权（均为调用失败/配额限制），按规则不计入任何分数；有效样本 {{Y}} 条」 |
| **R1-4** | 在没有交付战绩 JSON / 题库包 / 工具的情况下写「数据可复现」「一键复现」 | 目前无公开仓库、服务仅本机监听，第三方无从复现 | 按 §2.4 的 L1/L2/L3 降级表述 |
| **R1-5** | 隐去或混淆 **mock / 模拟模型** 与真实模型的区别 | 离线模拟体验用的是内置模拟选手，其成绩不代表任何真实模型 | 视频中一旦出现模拟选手，画面角标 + 简介双处标注「本场含模拟选手，成绩不参与任何真实模型结论」 |
| **R1-6** | 把「暂列第一」的 3D 画面剪掉，换成颁奖动画或加「冠军」字幕 | 画面与文案冲突会被立刻识破，且属于主动误导 | 保留原画面，用字幕解释「为什么这里不颁奖」——这本身就是最好的科普点 |
| **R1-7** | 用旧 v3.18 素材卡的文案模板直接照抄 | 该模板无条件输出「夺冠」，与 v3.35 口径冲突 | 按 §2 重填 |
| **R1-8** | 改动战报/海报上的数字，或在封面/标题上四舍五入制造差距 | 数字是原样对外证据 | 一位小数，原样搬运 |

### R2 · 表述失真（不违法，但会误导，发现即改）

| # | 绝不能这么写 | 为什么 | 正确写法 |
|---|---|---|---|
| **R2-1** | 把单场结果说成模型的**稳定能力**（「X 就是比 Y 强」） | 一场 = 一个评分期；单场样本量有限，且 CI 是按题重采样的 | 「在本题库本次调用下」+ 给出 CI；跨场结论只引用 Glicko 保守估计并注明场次 |
| **R2-2** | 把抽签/赛制的偶然性说成能力结论 | 赛制有种子排位与对阵树，一场的路径会影响观感 | 说明赛制（{{N}} 人固定对阵 / 同轮同题 / 加赛上限） |
| **R2-3** | 用**中转渠道/免费渠道**的一次响应，代表该厂商官方模型的水平 | 项目接了多个免费渠道（OpenRouter 等），同名模型可能来自不同渠道、不同量化/版本 | 阵容里每只都写「显示名（渠道）」；简介声明「不同来源的同名模型不作横向等同」 |
| **R2-4** | 把「裁判分歧」藏起来 | 多裁判会披露逐对 Pearson r 与逐题分歧度；藏了就是选择性呈现 | 「裁判 {{列表}}，裁判间信度 r={{值}}（n={{观测数}}）；n<3 不出数」 |
| **R2-5** | 宣称「无污染」 | 污染自检**只覆盖逐字记忆型**，改写/同义题测不出，方法学 §5 已明示 | 「已跑 canary 与污染自检（覆盖逐字记忆型，不覆盖改写型）」 |
| **R2-6** | 用「最」「第一」「史上」等绝对化表述 | 无对比基线 | 限定范围：「本项目已跑的 {{75}} 个罐中」「本场 {{N}} 只里」 |
| **R2-7** | 把解说（AI 生成）的修辞当成事实陈述放进文案 | 解说词是演出文本，不是评测结论 | 解说原话只出现在视频内；文案/简介一律回到战报数字 |

### R3 · 语气与分寸（不出错，但决定项目人设）

| # | 绝不能这么写 | 为什么 | 正确写法 |
|---|---|---|---|
| **R3-1** | 贬损具体模型/厂商（「智障」「垃圾」「割韭菜」） | 商标与商誉风险；且我们与厂商无授权关系 | 只描述数据：「本题 {{X}} 只失手，其中 {{Y}} 只给出了诱饵值」 |
| **R3-2** | 暗示厂商官方背书或合作 | 无授权 | 「本项目独立运行，与所涉模型厂商无关联；结果为第三方观察」 |
| **R3-3** | 标题党到与内容无关（「点开你会回来转的」「第一次投稿求支持」） | 平台明令禁止；且损耗信任 | 用 §2 模板 |
| **R3-4** | 用「AI 评测权威/标准」自我定位 | 我们是一个自测平台，方法学 §5 已列出 4 条已知局限 | 「自测平台，方法公开，局限明示，欢迎挑错」 |
| **R3-5** | 在简介/评论里放未授权外链或诱导站外交易 | 平台规则 | 只放平台允许的位置与形式（**待核实**具体规则） |

## 5. 冷启动建议

### 5.1 现状约束（先认清起跑线）

- 项目**此前 0 外部用户**：`serve` 默认仅监听 `127.0.0.1`，`sites/` 已作为独立仓库冻结，**无公开 git remote**。
- 也就是说：**观众点了简介链接也进不来**。这不是缺陷，是现状；冷启动方案必须在这个前提下设计。
- 反过来看：这条视频的**首要目标不是涨粉，是拿到第一批真实外部反馈**（见 §5.5）。

### 5.2 首发路径（三档，按顺序做，不要一次全铺）

| 档 | 动作 | 成本 | 目的 |
|---|---|---|---|
| **第 1 档（必做）** | B 站主片 + 同期 1 条切片，投**科技数码/知识**分区；允许转载；评论区置顶补充 | 低 | 拿到公开可讨论的锚点 |
| **第 2 档（主片同期）** | 在**允许发链接的 LLM/AI 开发者社群**（如 知乎专栏、少数派、掘金、相关 Discord/QQ 群、Reddit r/LocalLLaMA 类社区）发一篇**文字版**：讲方法（CI + 指纹 + 双裁判），**把视频当附件而不是主体** | 低 | 触达「在乎方法学」的人——他们才是会给有效反馈的人 |
| **第 3 档（视第 1 档反馈）** | 开放题库包/工具下载、或开一个只读的战报静态站 | 中 | 兑现 L2/L3「可复现」承诺 |

**首发时间**：以创作中心「粉丝活跃时段」为准；无数据时取工作日 19:00–22:00。**避免**周五深夜与周一上午。

**要不要允许转载**：冷启动期建议**允许**。这是一条数据可核的内容，被转载不会失真，反而省传播成本。

### 5.3 让人能复现（交付物包 —— 这是冷启动的真正杠杆）

按 §2.4 的档位准备，最低交付 **L1 包**：

```
{{罐名}}-{{日期}}/
├── 战绩-{{...}}.json        # 含 meta：题库指纹 / 裁判列表 / 工具版本 / 逐题 scores 与 votes
├── 战报-{{...}}.html        # 榜单 + CI 误差棒 + 裁判分歧 + 名场面
├── 题库包/                  # arena.json + 全部题目（L2 起）
├── README-复现.md           # 环境、命令、指纹校验方法、已知局限
└── 指纹.txt                 # sha256 前 16 位，供核对
```

`README-复现.md` 必须写清四件事：**怎么装 → 怎么跑 → 怎么对指纹 → 哪些数会变（模型版本与采样）**。
第 4 条最重要：不写清楚的「复现」会变成别人跑出来不一致时的信任崩塌。

### 5.4 第一批反馈怎么收

- **视频内**：结尾留一个具体问题（不要「求三连」，要「你觉得 {{罐名}} 这个测法公平吗？评论区告诉我哪一步该改」）。
- **首条评论（置顶）**：见 §5.7 模板，把「希望被挑错的点」列出来。
- **站外**：文字版里留一个明确的反馈入口（评论区 / Issue / 邮箱三选一，**不要同时开三个**）。
- **主动出击**：看到质疑科学口径的评论，**优先回复**、公开承认并补充数据。冷启动期一次高质量的公开纠错，比十条自夸更能建立可信度。

### 5.5 我们想从这条视频里学到什么（**这条最重要**）

> 这批反馈是**用户下一步方向的来源**。所以在投稿前就把假设写下来，否则看完数据只会说「播放量还行」。

| # | 假设 | 验证方式 | 看到什么就算验证 |
|---|---|---|---|
| H1 | 外部观众**在乎方法学**（CI / 指纹 / 双裁判），而不只是「谁赢了」 | 简介里 CI 与指纹的位置是否引发讨论；切片（纯高光）vs 主片（含数据解读）的完播率对比 | 评论区出现方法学提问；主片完播率 ≥ 切片 |
| H2 | 「不判胜者」的诚实表述**不会**劝退观众，反而会成为记忆点 | 若本场 inconclusive：观察「暂列第一」相关讨论的情感倾向 | 出现「难得见到说差距在误差内」类正向评论 |
| H3 | 有人愿意**真的去复现**（L1 包能带来至少一次独立核对） | 附件下载量、指纹核对反馈 | ≥1 条外部反馈提到已下载/已核对指纹 |
| H4 | 项目定位（全民电子蛐蛐 vs 严肃 benchmark）中，观众更吃哪一个 | 两套标题 A/B（主片 vs 切片）；评论区用词 | 出现明确的方向性偏好表述 |
| H5 | 有开发者愿意**贡献题库/罐** | 首条评论里的征稿话术是否被响应 | ≥1 条「我有个想法能不能做罐」的评论 |

**投稿前必填**：把 H1–H5 中本场**真正要看的 2–3 条**圈出来，写进 checklist 存档。

### 5.6 指标看板（投稿后 T+1 / T+7 / T+30 各看一次）

| 层 | 指标 | 看什么 | 决策阈值（建议） |
|---|---|---|---|
| 触达 | 播放、来源构成 | 是否出圈（非粉丝占比） | T+7 非粉丝占比 >70% 说明触达有效 |
| **质量** | **完播率 / 留存曲线** | 在哪一秒掉人 | 数据解读段是否出现明显下跌 → 下一期调整结构 |
| **质量** | **平均播放进度** | 内容是否被看完 | 与同分区均值对比（创作中心有对比功能） |
| 互动 | 评论数、**评论中方法学讨论占比** | H1/H2 | 方法学讨论 ≥20% 即验证 H1 |
| 转化 | 附件下载量 | H3 | ≥10 次下载 / ≥1 次指纹核对反馈 |
| 沉淀 | 涨粉、收藏、「催更」类评论 | 是否值得做第 2 期 | T+7 有 ≥5 条明确催更 → 立刻排第 2 期 |
| 风险 | 质疑/纠错类评论 | 口径是否被误解 | 出现口径误解 → **立刻发一条置顶澄清**，不等 T+7 |

**不要看的指标**：单纯播放量绝对值（0 粉丝起步没有可比基线）。

### 5.7 首条评论（置顶）模板

```
【关于这场的数据】（本条会随后续反馈更新）

· 名次只按答题均分。速度 / Token / 缓存是效率参考，不决定名次。
· 前两名分差：配对 bootstrap 95% CI = [{{lo}}%, {{hi}}%]。
```
