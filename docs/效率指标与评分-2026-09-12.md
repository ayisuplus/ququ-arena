# 速度、Token 与缓存指标

> **3.35.0 起**：新比赛改用 `quality-ci-v1`，名次只按答题均分，第一与第二的配对分差 95% 置信区间不含 0 才判胜者，否则只列"暂列第一"。下文的效率指标照常计算，在结算台和战报中作为"效率参考（不决定名次）"展示。下文描述的是 `quality-efficiency-v1`（3.34.4 及以前的战绩）的规则，旧战绩仍按它解读。

新比赛使用 `quality-efficiency-v1`，由竞技综合分决定结算台冠军。原始答题评分保留，生涯 Elo 继续使用答题质量的逐题比较；旧战绩没有新版本标识，回放按原规则展示，不重写历史。

## 默认公式

| 指标 | 基础权重 | 计算 |
|---|---:|---|
| 答题质量 | 70 | 裁判原始得分 q，范围 0–1 |
| 解题速度 | 15 | 同题有得分模型的最短解题时间 / 当前模型时间，最高 1 |
| Token 效率 | 10 | 同题有得分模型的最少总 Token / 当前模型总 Token，最高 1；总 Token 为 0 时系数为 1 |
| 缓存命中 | 5 | 缓存读取 Token / 输入 Token |

每题综合分 = `100 × q × (70 + 15S + 10T + 5C) / W`，本场对有效评分题等权平均。`W` 为当题实际启用的权重之和；某项停用时，同时从分子和分母移除。速度计算对不足 1ms 的时间按 1ms 处理，避免除零。

效率项也乘答题得分，所以答错的零分回答不能靠短、快拿分；零分答案也不充当其它模型速度与 Token 效率的比较基线。部分正确按得分比例折算。相同质量下，速度更快、Token 更少或缓存命中更高都会提高综合分。

同题任一参赛模型某项数据缺失，全体统一停用该项，按剩余权重归一化。重试时失败请求常常没有用量，因此标记用量不完整，该题全体停用 Token 与缓存项；速度仍包含实际失败重试与退避。输入为零时缓存率无定义，只停用缓存项。0% 与“未提供”严格区分，未知不补零。若各模型有效评分题目集合不同、比赛中止或没有有效成绩，不判冠军；并列使用未舍入的综合分，不用 Elo 打破并列。

例如两个模型都答对：A 耗时 2s、400 Token、缓存 0%；B 耗时 1s、200 Token、缓存 80%。四项完整时 A 为 **82.5 分**，B 为 **99 分**。如果任一模型未提供缓存数据，二者同时移除缓存权重，用其余 95 权重计算。

## 数据口径

- `solveMs`：从模型开始本题调用到得到最终答案，包含失败重试与退避；排除等待并发容量、裁判、解说和录制停顿。它包含网络及供应商等待，不等同于纯推理芯片耗时。`latencyMs` 仍保留最后一次成功调用的原值。
- `usage.input` 包含缓存读取和写入；`usage.output` 包含推理 Token。总量只做 `input + output`，不再加缓存或推理明细。没有输入/输出计数的接口不根据文本长度估算。
- OpenRouter/OpenAI 兼容接口读取 `prompt_tokens_details.cached_tokens`、`cache_write_tokens` 和 `completion_tokens_details.reasoning_tokens`，并支持直接接口的 `prompt_cache_hit_tokens`。流式用量可分批补发，重复快照替换统计，不重复累加。字段依据 [OpenRouter 用量文档](https://openrouter.ai/docs/cookbook/administration/usage-accounting)；缓存读取和写入的含义见 [缓存说明](https://openrouter.ai/docs/guides/best-practices/prompt-caching)。
- pi-ai 将非缓存输入、缓存读、缓存写分开，本次将三者相加恢复输入总量。该 SDK 一些接口会以默认零填充缺失计数，因此全零 SDK 用量保守视为未提供，零缓存不直接当作已证实的 0% 命中；正缓存读取可采集。兼容 HTTP 接口明确返回的零计数仍保留。此边界依据本机安装包 `dist/types.d.ts`、`dist/models.js` 与 provider 适配源码核对。
- 总览缓存率按已知输入 Token 加权：`Σ缓存读取 / Σ输入`，不对每次百分比作简单平均。显示已提供样本数和实际纳入计分题数；缓存写入不算读取命中。
- 各模型 tokenizer、缓存策略及接口覆盖不同；这是本场观测到的服务效率，不是同硬件性能测评。没有额外预热请求，也未修改供应商缓存策略。

## 展示与保存

工作台和擂台显示当前题耗时、Token、缓存率；本题全部结束后显示该题综合分。结算台增加综合分和缓存率，悬停综合分查看分项贡献及更多小数，顶部显示三项实际纳入题数。战报 HTML/Markdown 增加竞技综合榜，并区分答题质量榜。解说收到公开用量、速度、逐题综合分和最终结算，模板解说采用同一冠军。

记录、SSE 和时间轴保存新字段；刷新快照、新比赛回放复用保存的数据。重试时修复了一处已有边界：超时后迟到的旧答案必须清空，避免下一次重试也失败时被误当成有效回答。
