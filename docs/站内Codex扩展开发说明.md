# 站内 Codex 扩展开发

Harness 实验 →「让 Codex 帮我创建」。描述希望 pi 增加的工具、执行约束或上下文行为，Codex 在独立开发会话中制作便携扩展。原有「从模板创建」「导入配置 / 扩展」继续可用；配置内每个原生扩展也可交给 Codex 修改，回填时保留其他扩展和提示词阶段。

## 工作流程

1. 每个草稿保存独立源码、参数、原生 Codex 会话、逐轮回复、公开推理摘要、工具操作和功能检查记录。网页关闭不停止正在进行的开发；刷新按草稿标识恢复。
2. 左侧描述需求、追加修改或停止。右侧可查看、编辑源码及 JSON 参数。手工编辑有修订冲突保护；旧快照不会覆盖新内容。执行期间禁止并发编辑同一草稿。
3. Codex 读取本台实际支持的 pi 接口与示例，通过会话专属工具读写草稿、设置参数、运行功能用例。不会把文字中的“已通过”当作检查结果；最后源码发生变化时会重新检查。
4. 功能用例通过后，「保存为实验配置」把完整包交给现有配置编辑器。用户可组合其他扩展，再检查并保存不可变配置，然后选择开发集做基线对照。

## 功能用例

`extension-tests.json` 使用版本 1，包含 `cases`。每例有名称、明确标注的合成 `files`、有断言的 `steps`。支持真实工具调用、任务开始、上下文处理、任务结束，以及绕过扩展直接核对合成文件的结果。工具步骤经过真实 `tool_call → 工具 → tool_result`；测试结束检查 `session_shutdown`。每例使用新容器和新的 ExtensionRunner，状态不串例。

文件与用例格式的完整示例在 `arena/src/harness/authoring-tools.ts`、`authoring-tests.ts`，开发助手通过 `get_extension_guide` 获取，不要求用户记接口。最多 12 例、每例 20 步、共 120 步；每步必须有严格相等或字符串包含断言。工具返回及断言错误保留在检查结果，较长实际输出展示前 1000 字符。

这些用例用于验证扩展实现。用例由开发者编写，通过不等于 Benchmark 提分。Benchmark 的任务、隐藏验收和参考答案不会由开发工具提供；实验仍由 pi-agent 和独立冻结验收执行。

## 执行与计量

- 网站使用本机执行器和本机已登录的 Codex。未安装、未登录、运行环境未就绪会在面板中显示，不自动切换到其他 Agent。
- 每轮开发最多 5 分钟、80 次开发工具调用、6 次功能试运行；单次功能试运行最多 2 分钟。一个执行器同时运行一个开发或检查作业。每份草稿最多 20 轮、24 次完整检查，达到上限可从源码派生新草稿。
- 一份草稿开发一个便携 pi 包；保存配置时可以组合多个包。沿用 pi 0.85.1 的已支持原生工具/事件范围，不下载额外 npm 依赖，不支持终端 UI 扩展。
- Codex 原生会话保留只读宿主配置，仅开启当前草稿的受限 MCP 工具。扩展执行在无网络、无宿主挂载的隔离容器；执行器凭据、正式验收内容不进入该容器。
- 开发耗时、已报告 Token 和检查记录保存在独立的 `results/harness-authoring` 中，不计入 Harness 试验分数、用量或 Elo。Codex 提供线程累计用量时，按各开发轮次的增量记录；缺失用量显示未报告。
- 停止后拒绝晚到的输出和工具写入，保留已经保存的草稿。执行器重启将未完成作业标为中断，清理其所属测试容器，不自动继续消费 Codex 调用。

## 验证

见 `docs/validation/extension-author`。使用隔离数据完成真实 Codex 两轮创建/续改和实际 pi 工具用例，另用脚本化 Codex 会话验证网页失败、冲突、取消与断线边界。没有使用正式 Benchmark 验收答案开发扩展，没有因此宣称扩展提升了模型成绩。
