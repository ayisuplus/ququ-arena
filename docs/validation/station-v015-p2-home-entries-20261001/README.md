**后续验证：** [原生入口核对](native-entry-audit.json)九处入口189个采样均有承托、无通道碰撞，推导位置与实际场景相符；[六户Editor及两相位Player连续往返](../station-v015-p2-homes-20261001/README.md)各201项通过。下文保留入口推导的证据范围说明。

2026-10-01。在Unity港区构建等待用户关闭前方防火墙提示期间，先用已归档的源对象调查、迁移矩阵和对象映射定位下一批常住舱入口。

## 已确认的问题

`StationRoomIdentity` 是身份容器，不是门口或房间几何中心。源场景六个身份节点的位置均为世界原点，而墙体和家具子对象采用各自的实际位置；迁移后它们的根节点位置仍然不能代表入口。三个合住组身份节点还具有相同的根位置。以这些位置直接导航，会把角色送离房间；不能将[之前的根节点调查](../station-v015-p2-access-20261001/remaining-access-survey.json)的rooms.position当作行走目标。

本次读取原有成对入口墙体的包络，取开口中心，然后使用当前迁移方案的同一刚体变换推导R3局部入口坐标。保留原RoomId、身份节点与墙体在候选中的GlobalObjectId，供原生场景复核使用。既有建造脚本 `furnish_station_rooms.cs` 和 `build_model_homes_w4a.cs` 也与这些开口结构一致。

| 住处 | 入口层次 | 原墙体开口宽度 | 后续验证用途 |
| --- | --- | --- | --- |
| DeepSeek、ChatGPT、Claude | 每户建筑入口＋独立居住舱入口 | 约2.8m | 从外环街道穿过建筑，再进入真实居住舱，原路返回 |
| Gemini、GLM、Kimi | 每户居住舱入口 | 约2.2m | 经组团公共通道分别进入三户，不穿邻居房间 |

共六户、九处入口；身份根节点距离相应入口约93.6–143.1m，因此不能混用两类坐标。

## 可重复证据

- 执行 `python production/black-hole-station/v015/p2/derive-home-entries.py` 已成功，输出六户、九入口，源v014 SHA256与迁移基线一致。
- [entries.json](entries.json)记录源几何开口、目标R3局部坐标、入口前后2m辅助点、候选墙体ID及三个输入文件哈希。
- 脚本只写调查结果，不改Unity场景或存档。它不将原始身份节点重新定位，避免破坏现有引用和局部子对象关系。

**这是几何定位，不是通行通过。** 输入包络来源为已归档Renderer调查；实际Collider、入口前后2m是否有家具、穿过组团的完整路径、动态环相位与玩家带随仍须在Unity复核。墙体开口宽度不能替代门口净空验收。常住舱功能、居民路线和存档恢复也尚未完成。
