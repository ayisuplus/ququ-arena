# pi-agent Harness 实验台 · 2026-09-13

入口 `/harness`。固定一个真实模型，对基础 pi-agent、先规划、交付前复核或自定义阶段提示进行配对实验。代码任务直接调用 pi-agent 的文件和测试工具，由独立 Docker 容器验收；Codex / Claude 的旧原生实验保留在历史入口。

## 可用流程

1. 选择参赛模型、Benchmark 和任务子集。工程库有 6 个合成开发任务；文本库复用现有短题、开放题和多轮任务及评分标准。
2. 基础 pi-agent 固定纳入；选择扩展配置。可修改阶段提示、派生新版本，导入和导出配置 JSON。配置的内容哈希与版本随实验冻结。
3. 设定相同执行时限、最大调用次数、每次最大输出和重复次数。每个试验从独立上下文与干净代码工作区开始。一个任务中的后续轮次保留该选手自己的历史，不传入评分。
4. 查看逐题配对差值、平均耗时、所有参赛调用的已知 Token 与缓存字段、独立评分开销，以及完整调用/工具轨迹、补丁和验收日志。刷新不重跑；中止立即取消在途调用。
5. 评分失败保留答卷，仅重试失败评分。后续修改题库不影响冻结标准，变更裁判接口或模型会阻止补评。

运行记录在配置的 resultsDir/harness 中原子保存。协议导出包含冻结任务和每份证据的位置；单独导出各次试验可取得完整调用、轮次回答、补丁与日志。站点同步公开数据，模型密钥仍在本机。

## 科学口径与边界

- 质量与成本分别报告，未将竞技综合分或 Elo 用作 Harness 提升证明。执行失败计 0；环境失败、取消、中断或待评分会阻止完整配对比较。
- 同题同次重复配对，先在题内平均，再以题目为单位 bootstrap。少于两道独立任务不出区间；多配置区间为未校正的探索性描述，不自动宣布显著提升。
- 默认开发集；本项目已经用于开发的题目不能改标为保留集。该标记不意味着模型从未见过材料，也不等同于真正盲测。内置工程任务是公开合成开发题，使用者应独立复核题目和覆盖范围。
- 模型调用关闭 SDK 隐式重试；失败最多累计三次，共用原预算。已经发生工具操作后，不从头重放失败的提示。工具调用和最终文件保存受取消信号约束。
- 请求关闭显式缓存，无法保证供应商的物理冷缓存。未预热，也没有宣称热缓存实验；缺失用量或缓存字段显示未报告，不能视为零成本或零命中。
- 冻结请求模型 ID、接口哈希、pi-agent/pi-ai/Node 版本、运行代码哈希、Docker 镜像和评分标准。供应商的模型别名、推理默认行为、后台路由和硬件可能变化；记录接口报告的模型/供应商字段，不声称已冻结权重或远程硬件。
- 第一版扩展是 pi-agent 循环内的“规划”和“复核”阶段，可自定义提示与组合；不支持安装任意第三方 JavaScript/npm 插件。不接入文件工具以外的自主联网或宿主机命令。
- 桌面端实现；单次最多 24 道任务、120 个试验，并发为 1。长任务预算覆盖整项任务，含规划、复核和工具循环。

## 验证证据

`browser-checks.json` 记录 Sites 8183 隔离预览验收：1435×1078、1920×1080、2560×1440 页面布局，配置编辑、选择任务、启动、配对结果、完整轨迹、保留阅读位置、刷新不重跑、离线读取和原位模型连接状态。模型输出由独立合成接口提供，pi-agent、Sites 中继、执行器和持久化均是真实链路。原用户题库和战绩未用于测试写入。

内置浏览器 `cua.getState()` 返回 `nodeRepl.fetch request failed`，沿用用户之前授权的本机无界面 Chromium 验收。没有可用的原生 WebMCP 测试上下文；`configure_harness_experiment` 注册分支已实现，但不标为已通过原生 WebMCP 调用验证。

`test/harness.test.ts` 覆盖实际 pi-agent 流式循环、中文/结束补发、工具续接、扩展开销、三次失败、调用与时间预算、上下文隔离、取消、缺失用量、配置变更失效、冻结标准补评、并发补评去重，以及正常工程工具结束后允许无文字总结的文件交付。

发现并修复：Windows 同步读取可能暂时阻止快照替换，原子替换现对 EPERM/EACCES/EBUSY 作有界重试；目录尚未加载时搜索会读取空 settings，现安全等待加载；代码任务以文件产物验收，不因正常工具结束后缺少文字总结直接失败。逐模型连接检测也接受有效的推理或用量响应：推理模型在 32 Token 检测上限内没有最终答案，不等同于连接失败；真正空响应仍报错。

- `h-42577952-742a-49f4-84da-6e056b032b00.json`：硅基流动 Qwen3-8B，重复入账任务，基础与规划均触发三分钟执行时限。保留公开推理和失败，没有扩大该实验预算或改写分数。此早期验收记录的 thinking 字段为 off，但接口仍返回推理；当前协议已改为 provider-default，不把早期记录当成关闭推理的证据。
- `h-08a7eaff-873d-474c-9811-30e6ccb95806.json`：硅基流动 Qwen3.5-4B，分页任务。真实 pi-agent 完成读文件；规划配置实际修改文件并运行公开测试。基础配置遇到输出长度截断，规划配置在正常工具完成后返回空文字，触发了当时过严的文字总结检查。原始两个失败记录保留，当前运行时已修复后一个口径。
- `artifact-verification.json`：只用新 Docker 容器复核上述已有产物，没有重跑模型、没有追改原分数。基础文件通过 1/3 个验收分项，规划产物通过 2/3；后者仍未正确拒绝非法分页参数。两者整项任务均未通过。公开测试通过不等于正式验收通过。

这两次是实现验收样本，不构成扩展有效性的证据。真实 API 探测中，硅基流动可连接，Groq 返回认证问题，智谱返回限流，B.AI 此次检测未成功。新列表按钮可以重新逐个检测，不以已保存 Key 推断在线。
