# v21 角色近景与动作修复

- 入口：项目根目录 `Start-Game-v21.cmd`。
- 程序：`QuQuArena3D/BuildCharactersV21/QuQuArena3D.exe`，附带与 v20 相同的本机后台、Node 运行时及文件选择器。
- 版本化源文件：`production/characters-v21`；Unity 新资源：`Assets/Art/CharactersV21` 和 `Assets/Resources/Art/GalleryV21`。
- 保留 v19、v20、旧入口和原比赛资产；个人偏好文件的 SHA256 仍为 `24BC9DB0DBB45BF08D085605EECAFBA1E3AEBE988656224BF42CA84EDBA79F0B`。v19 程序程序集仍为 `FC8B5BB750E22ADC4E14C4DE49D650BD23A6C427C6CCE97625AAF4BCD84B6C8A`。

## 修复与边界

1. 展馆原来使用战斗前移动作，身体和头部保留防御姿态。六位角色改为各自原骨架上的 Meshy 日常行走；战斗动作不变。
2. Idle 和 Walk 的骨盆缩放不一致，切换时约有 1.18 倍的比例变化。统一为原始绑定比例，保持全身骨骼缩放连续。
3. 对六套动作分别校准着地高度和步幅，导航实际速度驱动播放速度。起停仍使用过渡；近看停稳后不再被导航避让挤动。
4. 新增独立的面部纹理、UV 和接缝法线修正，保留原角色身份。SSAO 改为与光照集成，避免把接触阴影直接叠到绘制型脸部。
5. 近看缩放范围扩展到 0.9 米，靠近时镜头从身体逐步移向脸部；沿用墙体碰撞约束。
6. 展馆失去窗口焦点后忽略鼠标输入，自动验收额外禁用输入设备，避免其他程序的点击改变测试状态。

本轮没有重雕整个人物，原约 2 万三角面的身体、服装、后部头发和复杂发饰仍有原资产的精度限制。面部生成细节属于艺术细化，不是原图中不可见信息的精确恢复。

## 证据与检验

`build-final.json`：Windows 构建成功，0 错误；唯一警告是未启用 Player 中的 Unity Pipeline 远程控制，不影响游戏后台。

`motion-comparison.json`：六位角色 × 两版本 × Idle/Walk，每个动作采样 25 个时刻。旧步行头部俯仰均值约 -26.7° 至 -27.5°；新步行约 +10.2° 至 +10.4°，站立约 0°。此值相对绑定姿态，正值向上。旧步行网格最低点范围约 -12cm 至 +9cm；新步行约 +0cm 至 +1cm。它是网格最低点检查，不是每个脚趾接触地面的证明。

`*-walk-samples.json`：每套新步行动作 49 个时刻的头、髋与双脚位置。`source-sync.json`：开发副本和项目源文件的逐文件 SHA256。`blender-sources.json`：12 个独立 Blender 文件的校验值。

`windows-01`：首次验收发现选中角色仍可能被导航避让推动，已修复；该次失败退出发生异常退出码，后台已停止并释放锁，不作为通过记录。

`windows-02`：六位近景和比赛结算通过；连续漫游阶段出现后台鼠标选中 Claude，经真实窗口确认后正常关闭，保留 `INTERRUPTED.txt`。它不是通过的十分钟测试。

`windows-03`：最终完整验收通过，600.001 秒连续漫游，同时最多三人行走，最小角色间距 1.281 米，运行错误 0。六位角色近看、缩放、环绕、Esc 导航、减少动态效果、三次进出和镜头恢复均通过。程序退出码 0，后台停止并释放数据锁。比赛验证使用已有结算事件夹具，明确不代表新模型调用测试。本轮没有改动后端、评分或比赛规则。
