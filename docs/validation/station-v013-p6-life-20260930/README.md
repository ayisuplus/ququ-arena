# v013 P6 居民咖啡厅停留与返家存档修复

本节点把 ChatGPT 居民的咖啡厅日常补成“步行到达—坐下—静坐—起身—返家”，兼容普通与 Q 版。其他五位居民保留原路线；四区居民活动和区域音景仍在施工。

## 实装

- 咖啡厅居民复用原 17 个路线点，追加两个座前接近点，最终点 `(207.65, 0.06, -196.4)`，朝向 180°，停留 30 秒。角色碰撞半径保留原 0.35 m。原住户、房间、咖啡厅与十个访客座位的身份保留。
- 坐下／静坐／起身来自 Meshy 官方动作库 57／33／53。已实际查看供应商 GIF 连续帧，再向现有普通与 Q 版骨架各提交三次动作；没有重新生成角色。
- Blender 仅导出原动作骨架。Unity 原生 API 将动作适配到现有角色修正后的骨骼比例，保持脚底支撑，按现有 56 cm 长椅适配位置。Q 版抬高坐姿并减轻头部前倾，短腿悬空。新增场景专用控制器，不修改展厅／赛事共享控制器。
- 居民接近时，访客不会入座到其身体内；访客先入座时，居民在最后一段入口等候，离座后继续。参赛时原居民隐藏、赛后恢复逻辑保持。
- 修复 `CaptureState()` 把返家最后一段目标 0 错写成 1 的问题。读取旧档时只对“旧编号 1、返家方向、位置确实位于最后一段”的状态修正为 0，保留 visits／returns；不接受任意离线位置。对白区分去公共区、休息、返家。

## 已验证

- [原基线](../../../production/black-hole-station/v013/p6-life/baseline.json)：六位居民均可往返，但六位都出现捕获状态无法恢复。运行时音源数为 **0**；此前从竞技场通用代码推测全局音乐的判断已纠正。本节点没有加入或替换音景。
- [最终回归](regression/residents.json)：Editor Play 内通过实际 CharacterController 加速推进 10,440 步，六位居民各往返一次；六份旧返家状态保留计数，1,836 次地面支撑采样通过；参赛隐藏／返回恢复通过。加速推进不代表真实键盘操作或性能压测。
- [座位交互夹具](regression/seat-use.json)：访客占座时居民等待、离座后继续、走到长椅、居民身旁访客座位拒绝进入，五项通过。
- [普通角色运行状态](runtime/standard.json)、[Q 版运行状态](runtime/chibi.json)：原生 Animator 实际处于 Seated 状态，角色在预定位置。下面是 Editor Play 观察相机截图；不是概念图，也不是独立 Player 截图。
- [首轮失败保留](regression-first/residents.json)：居中停靠点被桌椅夹住，只有五人完成。依据碰撞实测将停靠点侧移，恢复原 0.35 m 半径后复验通过，未移除桌椅碰撞。
- Win64 构建成功，`V013_BUILD_RESULT Succeeded errors=0`；[1,864 项来源快照](build-snapshot.json)逐文件核对哈希。输出为 `E:/builds/black-hole-station-v013-p6-life-20260930/BlackHoleStation.exe`，本轮未启动它。[场景身份复核](scene-preservation.json)确认 15,561 个原序列化对象 ID 全部保留，v012 文件哈希未变。

## 制作成本与边界

Meshy 六个任务共 **18 积分**，余额 **1456 → 1438**，无购买。任务 ID、文件 SHA256、动作参考与实际消费见 [资产记录](../../../production/black-hole-station/v013/p6-life/provenance.json)。[官方价格](https://docs.meshy.ai/en/api/pricing)于 2026-09-30 查询，提交前估价为每动作 3 积分，最终以任务实际回执为准。

站体、烘焙光照和家具几何未变，因此没有重烘焙。原角色长发／裙摆是骨骼蒙皮，局部折片仍可见，不把本次动作接入视作人物最终美术验收。用户尚未视觉认可本节点。

独立 Player 启动仍受 P5 时的自动审批策略拒绝（`Rejected: blocked by policy`）限制，本轮没有更换启动方式绕过。真实键鼠体验、独立 Player 运行、30 分钟性能趋势、四区日常与音景仍待完成。验证结束后主工程恢复干净 Edit 状态，测试写入隔离 QA 存档。
