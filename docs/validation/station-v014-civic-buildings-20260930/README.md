# v014 两栋公共楼、八间可进入的房间

2026-09-30。按用户追加的“多修房子，少种树”，暂停外圈扩种和整站铺装试装，转向完整房屋建设。本轮不新增树木。铺装候选未装入场景，草案留在本地.cache，不作为本次成果。

## 已落位的空间

东侧公共楼位于 `(166,0,30)`，西侧研修楼位于 `(-166,0,-30)`，西楼旋转180°。每栋建筑主体32×26m，约6.18m高，34×28m屋顶；中央4m宽走廊，两端开敞入口，四间独立房间各有2.4m宽门洞、完整墙窗和顶棚。

东楼为阅览、会客、公共交流和安静休息四室；西楼为公开档案、研修、讨论和安静工作四室。八间房各设一张圆桌、两组软包座椅及低柜，共16个可用座位。西楼另接入项目现有公开赛题档案台，读取现有比赛状态，不增加评分或后端结算逻辑。房间命名表达空间用途，没有新增会议预约、科研模拟或居民私宅系统。

既有四翼、居民住处和稳定ID保留；新座位采用 `v014-building-east/west-*` 独立ID。墙、顶、窗、门和低柜使用Blender精确制作，桌椅及档案台复用已接入模型与材质，没有拉伸家具或新增Meshy消费。

## 参考与修正

实际查看[Apple Park访客中心官方入口照片](https://www.apple.com/newsroom/2017/11/apple-park-visitor-center-opens-to-the-public/)，参考完整屋檐、通透外窗与大板材关系；没有下载照片作纹理。本项目保持银白、安静、高级科幻方向，使用已有珍珠白、缎面银、中性玻璃和灰米色软包。

首个候选位于 `(±159,0,±84)`。空间占用检查未与旧建筑相交，但实际控制器回归发现西楼挡住x=-147的科研导览通道。中间候选 `(±174,0,±30)` 又压到东侧休息区斜向旧路，因此最终向内退让8m至 `(±166,0,±30)`，旧路线保持；档案台也从门口移入角落，避免进入房间即被家具挡住。首轮路线失败和位置、画面保留在runtime的历史报告与attempt-01中。

室内门牌朝向在画面检查中修正。开工前还发现总览相机已有一个未保存的Unity默认URP相机组件，仅该新增组件和对象组件列表与磁盘不同；原样保留，没有更改其参数。此差异与本次新建筑分别记录，原有Transform、碰撞和Behaviour仍由保护核验检查。

## 验证边界

原生审计检查房屋、16个新座位ID、材质Shader、烘焙贴图以及30个屋顶覆盖／头顶净空采样。路线测试覆盖旧跨甲板、花园和导览路线，以及两栋楼走廊双向和八间房桌椅周边；座位测试覆盖原16座与新16座，档案台检查打开、关闭及移动状态恢复。最终Editor Play通过61条路线833段、约11.28km的控制器通行，以及32个座位和1个档案台共33项交互检查。报告见audit.json、runtime/walk.json、runtime/interactions.json、preservation.json。

场景保护核验保留29,325个原对象ID、12,582个原Transform／碰撞／Behaviour数据块。当前Console增量记录3条既有QuickInstaller中文路径字节转换异常，以及1条CrashReporter线程断言；不宣称Console零错误，详见console-errors.json。

测试在Editor Play中通过CharacterController.Move和交互API执行，逐条路线起点放置，居民交通隔离；不代表真人键鼠、独立Player或30分钟性能验收。原Editor存档逐文件备份恢复，测试存档不入Git。

最终光照、48个自定义反射探针完成后才同步Win64构建；构建结果和当前源输入逐项哈希见build-result.json、build-snapshot.json、artifact-check.json。本次Win64构建成功，0错误、1条既有RuntimePipelineConfig缺省警告，776,817,251字节，2,495项当前源输入哈希一致。本轮未启动独立Player；此前该动作被自动审批以 `blocked by policy` 拒绝，没有换方式启动。

制作与复现脚本在 `production/black-hole-station/v014/civic-buildings/`。`build.py` → Unity原生`install.cs`；安装仅用于不含本组建筑的已保存v014。后续GI、反射、审计、通行／交互、截图与构建分别验证。
