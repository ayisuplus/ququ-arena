# 东侧公共连接口与北侧连续漫游：验证

日期：2026-09-28。候选场景：`Assets/Station/Scenes/BlackHoleStationObservatory.unity`。施工依据为[方案 v008](../../黑洞空间站升级方案/施工方案_v008.md)的居住区→站外接驳→赛场连续路线，以及[最初空间站总览图](../../黑洞空间站升级方案/08_概念图/IMG-001_空间站总览_v001.png)的外方框、内菱形和北侧抵达轴线。

## 发现与修改

在改动前，Editor 角色控制器从玩家舱室经南侧公共绕行到停靠舱、再回赛场，实走 **1374.4 m／6875 步**。东侧居住区与已有公共绕行廊之间只有一段 x=120、z=91.5..120 的外墙挡住；z=105 位于最后一间私人房间北缘 z=96.5 以外，墙内外都有实体地板。本轮将该墙分成两段并加顶梁，留出 z=101..109 的公共入口，不改三扇私人房间压力窗，也不穿越房间。

[居住侧看入口](residence-to-bypass.png)和[绕行廊看入口](bypass-to-residence.png)是已保存场景的 Editor 实渲染。它们显示的是几何灰盒；居住主区的完整屋盖和气密分区尚未建成，不能把这个入口称作已通过压力密封验收。

## 验证

- `verify_east_residence_public_connector.cs` 从磁盘重开场景：入口直线无碰撞，横穿原墙位置的 **32 个地板采样点**连续，私人压力窗碰撞体仍为 **3** 个。场景除被替换的 `East outer wall segment 6` 外，原 GameObject 名称均保留。
- [Editor 新路线](editor-direct-route.json)：玩家舱室→东侧公共入口→北侧停靠舱→赛场固定落脚点，**628.0 m／3143 步**，十次舱门操作后全部关闭，场景不切换。相比施工前同起终点绕行，少 **746.4 m**；这只说明交通路径更合理，不代表可玩内容已经足够。
- [原有路线回归](editor-existing-routes.json)：上层完整闭环 **864 m**、下层完整闭环 **680 m**、原东侧与西侧公共绕行以及住处→上层→下层→船坞连续路线均通过，说明新入口没有切断旧路线。
- 首个独立 Win64 Player 从住处真正步行到停靠舱、在舱内关门并保存：[写档结果](player-accepted-write/write.json)为 **408.1 m／2042 步**、`loadSource=fresh`、舱内坐标 `(12, 2.28, 245)`。第二进程从该坐标恢复，走回赛场并保存：[读档返程](player-accepted-read/read.json)为 **263.8 m／1321 步**、`loadSource=primary`、最终坐标 `(35, 0.08, 20)`。第三进程[再次载入赛场坐标](player-accepted-confirm/confirm.json)；三个进程退出码均为 0，两次步行的地板支撑、各 6 次舱门操作及最终关闭状态均通过。两次实走相加比 Editor 628 m 多出的约 44 m，是写档前在舱内往返关门的检查路径。
- `StationWorldSave` 原先排除中心 43 m 内的一切存档点，导致赛场固定落脚点只显示 `SaveNow=true`、实际仍存旧停靠舱坐标。边界调整为 40 m 后，Editor 检查固定落脚点和停靠舱为安全点，38 m 环台内侧与中心井仍被排除；最终 Player 第三进程证实赛场坐标可重新载入。测试用存档位于被忽略的独立构建目录，没有读写用户的正式存档。

最终构建为 `QuQuArena3D/BuildVNorthShortcutV03/BlackHoleStationWorld.exe`；[构建日志](build-accepted.log)含 `World preview build: Succeeded`。源场景 SHA-256：`20BAF3BBAADEFB60CF1A5CF2EC4B2F8816E55E27E81B126C871FE37C86D45772`，构建 `level0` SHA-256：`B3348BC3846D5A85DE26EE1B1B75F73B51AC36F628DF4A49447F2D0EEAE36428`。[初版构建日志](build.log)和[第二版日志](build-final.log)保留作失败边界追踪；初版读档虽到达赛场，但未验证最终存档坐标，因此不作接受证据。
