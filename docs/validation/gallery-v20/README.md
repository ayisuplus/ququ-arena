# v20 角色观测舱验收

## 范围与证据

在 v19 科考站基础上新增独立角色展馆；比赛引擎、后端接口、现有战斗资产与存档格式不变。展馆只使用六个内置角色，不产生模型调用。

Blender 源文件与建模脚本位于 `production/gallery-v20`。先输出灰模并使用 Unity 实际镜头检查，再调整展馆到竞技场后下方、完成正式材质和低成本室内照明。`gray-home.png`、`gray-arena.png`、`gray-interior.png` 是灰模阶段截图。正式场馆共 16,580 个三角面；室内、六个角色和六盏无阴影白光只在参观时启用。

Windows 测试使用独立数据目录，PATH 仅包含 Windows 系统目录，由发行版自带的 Node 启动后端；不迁移个人数据，不调用模型。比赛并行测试回放保存的比赛事件夹具，检查攻击、胜者结算与相机所有权，不能将该项表述为本轮重新调用模型进行了一场比赛。

## 构建与修复记录

- `build-05-summary.json`：最终 Unity 6000.3.24f1 Windows 构建成功，0 错误。唯一警告是现有 RuntimePipelineConfig 缺失，发行版未启用 Unity CLI 运行时连接；游戏本身可正常启动。
- `windows-01`：发现关闭动态效果后 NavMesh 避让仍能轻微推移角色；修复为同时冻结代理位置同步与动画时间。
- `windows-02`：冻结、返回和结算测试通过。人工实机观察发现手臂累计偏移，主动正常关闭测试程序进行修复；退出时产生的寻路断言是此次中断的结果，不能视为自发穿墙。移除逐帧叠加姿态，改为烘焙有界循环动画；保留原行走周期，并增加十分钟手部姿态检查。
- `windows-03`：连续 600.0085 秒漫游通过，最多三位移动，最小角色中心间距 1.282586 米。六人累计到达 20–24 次，累计移动 207.7–273.1 米；包含测试前的点选与进出过程。少数会车触发停下、重新选点，之后均继续活动。运行错误为零，正常退出、自启后台关闭、数据锁释放全部通过。
- `build-04` / `build-05`：人工输入检查发现展馆滚轮按原生 Windows 单位计算，当前 Input System 实际默认返回 ±1。修复展馆缩放系数，并加入仅由 `--arena-gallery-input-check` 启用的诊断日志；默认运行不输出该日志。最终发行程序集已核对包含新系数。此后只改变展馆输入处理和诊断，不改变漫游、动画、场馆资产或渲染，因此沿用 build-03 的十分钟及性能记录。

## 实机交互记录

首页“模型展馆”和场景设施标识均已实际点击进入；名单点击 Claude、鼠标左键拖动环绕和俯仰已验证。最终版 `interactive-03.log` 记录真实滚轮值 ±1、`overUI=False`，观察距离逐格变化 0.48 米，最小值限制在 1.7 米。该输入记录包含用户的操作，不能称为全程无人接管。

用户短暂接管窗口后停止鼠标注入，收到“继续完成验收”后恢复。最后直接点击场景中的活动角色进入 DeepSeek 近看；四格滚轮输入为 +4，距离从 5 米缩至 3.08 米，反向四格恢复 5 米。随后实际键盘 Esc 依次返回全馆、赛场，结果正常。已正常关闭隔离验收实例；使用的数据目录为 `E:/tmp/ququ-gallery-v20-interactive-03`，不会修改正常游戏偏好文件。最终退出检查见 `interactive-lifecycle.json`。

## 回退与重现

运行项目根目录 `Start-Game-v20.cmd`。v19 的 `Start-Game-v19.cmd` 与 `QuQuArena3D/BuildResearchV19` 保留。源代码修改前副本、旧程序集哈希和个人配置哈希记录位于 `production/gallery-v20`。

`preservation.json` 确认 v19 程序集与个人配置哈希未变；`source-hashes.json` 确认 94 个新增及关联源文件、资产与构建暂存工程一致。后端 Node 24.15.0、依赖锁与依赖清单和 v19 相同。Meshy 任务、模型调用和相关消费均为零。

重新验收：在没有游戏运行时执行 `production/gallery-v20/validate_windows.ps1 -Run windows-04`，使用未用过的 Run 名。自动流程约 13 分钟，期间不要操作游戏窗口。需要原有保存事件夹具，所有数据写入新隔离目录。
