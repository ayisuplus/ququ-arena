# v015 P4：圆形竞技场与梯级看台

2026-10-01，基于 `eb00e974` 继续景观施工。用户明确要求看台类似罗马竞技场，采用环绕式圆形梯级。实际候选为 `BlackHoleStationThreeRingBuildingsV015`，新增看台、外壳与通行均属于 R1，随内环正常缓慢旋转。

## 已建形态

- 九级瓷白看台围绕原中央贯通井展开；八个弧形座席区，前八级配置蓝色弧形长座面，最上层复用103把原装饰座椅。座面、台面、屋檐和外立面均呈圆形，不再沿用方形/L形看台。
- 四条放射楼梯连接下层赛场边缘与上层完整环廊；四条外侧弧形坡道提供另一条上楼路线。每排座位在楼梯侧留入口，先从台阶进入排侧，再转入座面后方通道。
- 四向底层通道穿过看台组团。东西两侧原选手升降井保留，公众从井侧绕行，不能沿入口轴线直穿升降孔。
- 圆形曲面屋檐盖住外围环廊，内缘退到半径62m，使梯级看台完全可见。瓷白主体、蓝色座面和玻璃、少量银色收边复用现有材质；未改全局曝光。
- 原唯一功能观赛座位的对象、位置和引用保留；103把装饰椅只迁位和转向，原尺寸、子物件及身份保留。旧直线坡道、L形高廊及其防护原对象保留但停用。旧空白题目板及支架因切穿新看台而保留停用，后续随赛事呈现单独整理；本轮不启用真实赛事。

[初版静态失败记录](stand-audit-initial.json)保留456项：12项来自沿入口中线穿越原升降井，后续明确改走井边；444项来自楼梯检查探针把脚部台阶也当成上身穿透，改用既有上身净空高度后复核。实际角色是否能走台阶仍由Player实走判定，不能把修正检查器解释为修复了444处场景缺陷。

首轮实际通行[相位0](player-phase0/stands.json)/[相位97](player-phase97/stands.json)均在第一条楼梯下行失败：正常6m/s下行时角色靠重力下落，短暂高于台阶约0.40–0.43m并丢失地面参考；四条坡道与完整环廊此前已通过。这是实际移动缺陷，未通过减慢测试速度或抬高通过阈值掩盖。`StationGrayboxWalker.MoveOnGround`补充向下贴地：仅前一帧有地面承托且正向下移动时，在既有stepOffset加skinWidth范围内寻找脚下可走台面；更大落差仍自由下落。修正后重建Player，另回归跨环接缝和高位路线。

第一版修正仍有承托失败，保留[相位0](fixed-phase0/stands.json)及[相位97](fixed-phase97/stands.json)。[局部诊断](stair-diagnostic/stands.json)确认角色 `isGrounded=True`，但中央射线到低一级台阶约0.575m，超出原0.5m取样长度；胶囊实际由旁侧高一级台阶承托。因此已有承托时，地面识别也按同一stepOffset加skinWidth范围采样。座位侧向通行入口定位改为每层首级踏步内侧，避免从较高的第二级侧面硬爬回楼梯；玻璃护栏与座面尺寸未再缩小。

首版[高位路线回归](upper-regression/upper.json)有两项承托失败：新探针从错误方向接近原功能座位，擦过其椅背，角色短暂踩上椅子。已将末段改为沿环廊绕至座位侧面，原椅子没有删除、停用或缩小碰撞。该失败保留，不算通过记录。

[原生场景差异](scene-diff.json)确认没有删除原序列化记录、没有改变原MonoBehaviour记录；改动原Prefab实例均为103把迁位座椅。[文件哈希](checkpoint.json)绑定最终候选、网格、脚本、截图与验证输出。

此前P2的直线看台/护栏压力结果只适用于其历史几何；本轮圆形看台使用新的路线探针。`StationRingUpperProbe`对新圆形候选走外围坡道和环廊，对历史候选仍保留原路径。旧 `StationRingUpperGuardProbe` 的L形看台坐标不适用于本轮候选。

## 复现与边界

脚本在[production/p4-arena-shell](../../../production/black-hole-station/v015/p4-arena-shell/)。原生创建顺序为 `create-shell.cs` → `create-circular-stands.cs` → `refine-row-access.cs`，仅适用于对应前置版本；最后一步不是幂等操作，不能在已完成场景上重复运行。所有原生资产均通过Unity API创建和保存，未手改场景YAML。

构建菜单：`Tools/Station/V015/Build circular stands`。`run-player.ps1`使用新的绝对证据目录，支持 `stands`、`spectator` 和 `upper`，相位0/97。探针只在明确命令行参数下启用，正常启动不运行。

`-StairsOnly`只跑一条楼梯及其八排侧向入口，`-GuardsOnly`只跑四处护栏压力，报告中的scope区分局部与完整路线。[完整路线构建绑定](route-validation-build.json)记录该次运行的程序集、场景与移动脚本哈希；其后仅加强验证探针的护栏接触断言并调整护栏取样角度，场景和移动实现未改，再单独验证护栏。没有以局部测试冒充重新执行全部路线。

未启用斗蛐蛐后端、未接通完整世界存档，未进行整站性能验收或最终用户审美确认。上一轮两处整站圆弧偏差仍见[原景观记录](../station-v015-p4-landscape-20261001/README.md)，本轮局部检查不能视为其已修复。前置 `ArenaFont.asset` 和其他非本轮资产保持，自动提交仅包含本轮可归属变化。
