## 5. 配额与成本

### 5.1 成本模型

一次调用 = **1 个（题 × 蛐蛐）对**。`exact` 裁判的罐**不额外产生裁判调用**（默认 `--judge mock:laoshi-k2` 只在需要 LLM 裁判时才真调）。

OpenRouter 免费档硬顶：**50 次 / 日**（`free_model_daily_requests`），**且是账号级共享——换模型、CLI 与 3D 客户端之间都不重置**。

| 推荐罐 | 蛐蛐数 | 理论调用 | 占免费额度 | 今天打得动？ |
|---|---|---|---|---|
| **excel-survivor（6 题）** | 4 | 24 | 48% | ✅ 余 26 次做重试 |
| **excel-survivor（6 题）** | **5** | **30** | **60%** | ✅ **推荐** |
| excel-survivor（6 题） | 6 | 36 | 72% | ✅ 余 14，偏紧 |
| pattern-grid / kb-fringe / case-extract（12 题） | 3 | 36 | 72% | ✅ |
| number-sequence / verify-claim（16 题） | 3 | 48 | 96% | ⚠️ 不建议 |
| stroop-test / truth-lie / dyck-bracket（24–26 题） | 5 | 120–130 | 240–260% | ❌ 免费档要 3 天 |
| cipher-decode（30 题） | 5 | 150 | 300% | ❌ 同上 |

**今天的实际消耗**：`50 → 剩余 4`（核验开始时 `remaining:50`）。今天已经打不出东西了。

### 5.2 风险 1：429 上游限流会在 3 秒內灭掉一只蛐蛐（**今天真实发生了**）

不是"额度用完"，是 OpenRouter 替我们把请求转给上游 provider，上游的**免费共享池**在限流：

```
{"error":{"message":"Provider returned error","code":429,
 "metadata":{"raw":"z-ai/glm-5.2:free is temporarily rate-limited upstream. Please retry shortly, or add your own key to accumulate your rate limits",
 "provider_name":"Decart","provider_error_code":"overloaded","limit_source":"upstream_provider_shared_pool"}}}
```

引擎的保护是 `MATCH_LIMITS.failures = 3`（`src/battle-resilience.ts:2`）：**累计失败 3 次就退赛，且失败计数全场累计、跨题不清零**。Stroop 那场 qwen/GLM 在开赛后 **3.5s / 4.1s** 就被判出局。

**规避（按优先级）：**

1. **只用今天实测存活的模型**：`nemotron-3-super-120b-a12b`、`nex-n2.5-pro`、`lfm-2.5-2.6b`（+ `inclusionai/ling-3.0-flash-vl` 待验）。别重复踩已 429 的。
2. **先小规模试再放大**。正式拍摄前先用 `--limit` 打 2–3 题确认每只蛐蛐都活着，别一上来就烧掉一半额度。
3. **别把阵容全押在同一家 provider 上**（现在的名单里 Nvidia / Nex AGI / Liquid / Novita 已经分散，这是有意为之），共享池限流是分 provider 各自计数的。
4. **一旦某只蛐蛐开始连续 429，立刻换模型重开**，别指望它自己恢复。
5. 引擎对 `free-models-per-day` / `free-models-per-min` 各有一层进程内熔断状态（`src/openrouter-limits.ts` 的 `recordOpenRouterError` / `assertOpenRouterAvailable`），打到每日硬顶会给出明确的"已用完 + 重置时间"报错——那种情况是**干净失败**，不会污染成绩。

### 5.3 风险 2：硅基流动会造出"假 0%"（**今天也真实发生了**）

硅基流动的两个模型**答案全对，但因为慢被判负**。实测延迟 **27.7s / 33.3s**（还只是让它们回两个字）。truth-lie 那场 Qwen3-8B 有 **4 条空答案**、Qwen3.5-4B 有 **5 条空答案**，全部来自 `TL-chain-5-01` 的 `单题超过 60 秒未完成，已退赛`。

而 `src/runner.ts:361` 把 `timeoutMs` 钳到 `Math.min(传入值, MATCH_LIMITS.questionMs=60000)` → **CLI 没法抬高单题超时**。

> 后果就是分工里点名的那个坑：**迟到被记成不会做**。观众看到会以为那个模型真的很菜。
> 结论：**除非它能把单题延迟压到 20s 以内，否则硅基流动不要进正式阵容。**

### 5.4 风险 3：付费渠道额度未知

硅基流动的余额接口已经下线：`GET /v1/user/info` → `{"code":20092,"message":"This endpoint is deprecated and is no longer available."}`，`/v1/account`、`/v1/billing/credit` 均 404。**我不知道它还有多少钱**，没法承诺能打 130 次。要用就得充值并目测。

### 5.5 错峰 / 分批建议

- **分批**：24 题以上的罐想靠免费档打完，只能拆成 2–3 天。但跨天意味着不同批次题目的阵容状态不同，**剪辑出来的比赛不是同一场**，拍摄和结算都别扭。不推荐。
- **错峰**：UTC 凌晨用户少，429 概率下降（推测，未实测）。
- **BYOK**：OpenRouter 的 remed 提示得很直接——"add your own key to accumulate your rate limits"（`https://openrouter.ai/settings/integrations`）。给目标厂商挂一把自有 Key 是唯一解除"共享池限流"的办法。
- **最省的做法**：见 §4.2，`/replay` 让拍摄与配额完全解耦，重拍免费。

## 6. 已知边界（诚实清单）

**没验证到的：**

1. **Unity 图形界面没实跑。** 为避免抢占用户前台（无边框全屏 + 可能有背景音乐），本轮只做到无头启动（`Loaded All Assemblies` 无异常）+ 复刻方式跑通它要拉的后端。最后一环请人工点一次 `Start-Game.cmd` 确认。
2. **`excel-survivor` 没有实跑。** 今天剩 4 次免费额度，不够打一场 6 题 × 4 蛐蛐 的验证赛。它的"区分度"是推断，不是数据。
3. **`inclusionai/ling-3.0-flash-vl:free` 只做过单发问答**，没进过正式比赛。
4. **OpenRouter 免费额度的重置时刻未实证**（响应里 `x-ratelimit-reset` 头是 null）。推测按 UTC 日界重置；建议开拍前先打一次 `/api/v1/key` 看一眼余量，别打到一半才发现清零。
5. **Web UI（`serve`）的实际观赛演出没逐屏验证**；v3.34 起演出已移交 3D，本轮只验到路由 HTTP 200 和 `/replay` 能出帧。
6. **免费额度计数器的口径未核实**：我发现部分 429 失败请求也计入了 `used`，做估算时按「每次调用都计数」的保守口径处理。
7. **"没有区分度"这个结论有适用边界：** 今天被否决的三个罐，否决依据是**当前这批模型**在**只跑 5–10 题**上的表现。换一批更强/更弱的模型、或题数拉到 20+，结论有可能翻 —— 拍摄前若在目标阵容上复测，请以复测结果为准。
8. **环境幂等性：** 我启动过两个后端（8199 / 8200），也拉起过一次无头 Unity，临时 `BackendData` 目录已删；`arena/results/career.json` **未被改动**（mtime 仍为 2026-09-18 10:14）；未提交 git。
9. **`doctor` 的 API Key 假阴性**（§1.0）会让初次接手的人误判"真实模型不可用"。我没有改代码，仅记录。
