# v014 四栋公共楼后的编辑器性能基线

基于 `0c316b50` 已保存场景，四栋公共楼、16间房、40座和外立面均保留。本轮只增加诊断脚本与记录，未修改游戏场景、渲染设置或运行时代码，未新增树木。

## 实测结果

RTX 5090 / Ryzen 9 9950X3D，Unity 6000.3.24f1，D3D12，主相机3840×2160，URP renderScale=1，VSync=0，无目标帧率上限。七个固定机位各预热3秒、采样10秒，合计约91秒；通过 `endCameraRendering` 与 `Time.frameCount` 去重，确认主相机实际提交渲染，共19421次。间隔由相邻渲染回调时间计算，包含编辑器调度开销，**不是独立Player帧率**。

七个采样窗中超过33.33ms的间隔均为0；预热及切换机位的开销没有计入。GPU数据来自FrameTimingManager，仅统计有效正值。本次未发现需要削减新建筑的性能证据，也没有进行未验证的画质降级。

咖啡厅背向屏幕仍产生1914次转播相机渲染：现有逻辑按30米距离刷新，不检查屏幕是否进入视锥。列为可比较的后续优化项，本轮未改变行为。两个咖啡厅机位可见建筑不同，**不能把二者的耗时差直接归因于转播成本**。

## 范围与限制

- 机位只移动玩家相机，玩家控制器暂停并保留原位置；居民与其余场景系统继续运行。它是固定画面的渲染基线，不是步行、门口接近交互、居民完整循环或真人键鼠体验测试。
- 未主动启动赛事或调用付费模型。未覆盖激烈比赛、所有特效和后台服务压力，不对真实比赛负载作结论。
- UnityStats约1329–4917批次、609万–1979万三角形，可能合并编辑器视图与附加相机工作，不能当作单一主相机的准确绘制负载。
- Unity已分配内存样本约1.29–1.36GB，包含编辑器、诊断列表与机位切换分配。91秒不足以判断内存泄漏或30分钟趋势。
- 自动存档组件暂停并改为临时输出路径；进入Play前备份、停止Play后按SHA256还原原档。本轮没有覆盖保存负载。
- Console新增1条已有QuickInstaller的非法字节序列异常（seq1905）；没有宣称零错误。该异常与此前记录同源，尚未修复。
- Play已停止，场景无未保存修改；未启动独立Player，未新增构建。现有Win64构建仍为上一轮外立面版本。独立游戏、目标设备30分钟、完整交互与用户视觉认可继续待验。
