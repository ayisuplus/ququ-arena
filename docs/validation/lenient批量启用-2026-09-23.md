## 5 · 副作用说明：历史战绩与新战绩的**口径不一致**

**本次改动改变了 53 罐的判分口径**（严格 exact → lenient），因此旧战绩（严格口径产生）与新战绩（lenient 口径）对**同一条「答案对、多说了话」的作答**会给出不同分数。项目已有内建的分卷机制，影响范围有界：

1. **题库指纹会变**（`src/fingerprint.ts` 的 `evalPayload` 明确把 `judge` 与逐题 `judge` 纳入哈希）。实证（`.local/t011/fingerprint-diff.ts`）：

   ```
   anagram-check    旧指纹 36ae3fb79c0b0fa0  →  新指纹 2e6322d43aa34d42
   province-plate   旧指纹 d86666c9442ac501  →  新指纹 831dddb59c2fc2de
   statute-match    旧指纹 d83b78799a7c67ec  →  新指纹 8514e85bda7d244d
   truth-lie        旧指纹 2c1d336eecba2a65  →  新指纹 b1718ab1fa02b19a
   ```

   即**旧战绩与新罐不再同卷**——这是既有设计（`commands-admin.ts`：「同名片版本变更：旧指纹 → 新指纹（历史战绩与新罐不再同卷）」）。
2. **受影响且有分卷保护的地方**：`experiment-protocol` 的严格同卷对比（指纹不同会**拒绝**跨口径比对）；`game-duel` 分析按指纹分组；战报/论文/海报均披露指纹。→ 跨口径的证据不会被静默合并。
3. **仍会**把两代口径混在一起的**按罐名聚合**呈现：生涯成就按罐名记录（`career.ts:172`）、数据集/导出文件名按罐名、首页按罐名罗列。同一模型在同一罐、跨越改动日的正确率会混入新旧两种口径；**但每条战绩的 JSON 都带 `meta.arenaFingerprint`**，仍可事后按指纹拆分。
4. **先例**：v3.35 对旧口径的做法是「**按当时规则展示、不重算**」。本次沿用该先例：**不重算历史**。
5. **是否需要提示文案**：本项目**已自动**在榜单/战报披露指纹，口径变更天然可归因，**判定为「无需新增运行时提示文案」**；建议仅在 `arena/CHANGELOG.md` 记一笔「本次口径变更」以便人类对照（**是否落 CHANGELOG 由主理人定，本轮未改 CHANGELOG**）。

## 6 · 未验证与边界（诚实清单）

1. **真实收益只在 truth-lie 有人工作答样本**：本轮**零真实模型调用**，其余 52 罐的「lenient 会让多少条真实作答由错转对」未逐罐复算——实证仅到「多余前后缀型必转正、真错必仍判错」的规则层。
2. **假阳性（本方案固有代价）**：`lenient` 只接「薄包裹」（前缀 ≤4 字且以系动词/冒号收尾或整段为导语，且不含否定词），但**仍可能**放过「异主语但答案字面吻合」的作答（问「戊」答「甲是老实人」——前缀「甲是」合法）。该风险与 T-007 的人工宽松口径同源，本轮**不额外放大**，并用「宁严勿纵」回归用例钉住边界（否定/超长前缀/疑问/真错一律判 0）。
3. **不覆盖**：英文导语（`The answer is panda`）、等价改写（`雨`↔`雨水`）、串式分隔符变体、日期补零——分属第 2/3 类，走 `alternatives`/`llm`，本轮未动。
4. **停战罐未纳入**：`digit-slang`/`emoji-quiz`/`soup-lateral`（以及串式的 `event-order`/`sentence-order`）本轮不评、不改。
5. **`core-arena`/`metacog-gate` 归第 3 类未启用**：二者答案为混装（含长尾/串式），本轮保守不动；若后续评估认为短答子集收益明确，可单独再议。
6. **全量 `node --test` 整批挂起**：见 §3.2 注（与本改动无关的环境问题）。
7. **未提交 git**：工作区 300+ 未提交改动一概未动、未清理、未提交。
