## 三条实际逐帧路线

独立Win64 Development Player使用候选02、D3D11、60fps目标、原Walker的6m/s步行参数；环仍按正常慢速运行。分别从内/中环±0°、±97°及外环0°、48.5°开始。仅在独立路线起点放置角色，中途不瞬移、不加速时钟。固定带按圆弧行走，目标街口每帧按所属环转换。

1. 固定抵达前庭 → 外环街巷 → F-B → 中环咖啡前庭 → F-A → 内环赛事入口。
2. 原ChatGPT住处对应前庭 → 中环科研前庭 → 返回同一住处随环移动后的位置。
3. 住处 → 生态园前庭 → 外环观景步道 → 回到同一住处；全程留在R3。

每段检查到达、无掉落/台阶、无包络穿入、圆弧偏离；停留检查所属环与局部位置稳定。开始相位不同会改变要沿固定带走的距离。验证路线是明确的可通行路线，不宣称最短路径；距离/时间不能作为最终导航或舒适度验收。

运行记录：[相位0](routes-phase0/daily.json)、[相位97](routes-phase97/daily.json)。每条大路线完成时另写阶段快照，`daily.json`才是整套最终结果。相位0的首条路线约631m，相位97约814m；前庭路线不包含进屋、喝咖啡、交互观赛或居民AI。

两套最终结果均为131/131项通过：相位0为35,865帧、598.0秒、累计3533.3m；相位97为36,192帧、603.5秒、累计3569.7m。累计距离包含三条路线中的全部去程和回程，不是单次目的地距离。运行设备RTX5090，结果不构成整站性能或最终导航效率认可。

构建见[build.json](build.json)。复现：菜单`Tools/Station/V015/Build three ring layout`；使用[run-layout.ps1](../../../production/black-hole-station/v015/p2/run-layout.ps1)传入新绝对输出目录和`-Phase 0`或`97`。原生构建前先编译并等待完成，编译和构建之间不要运行eval。每次使用独立QA存档，未动用户旧档。

[Editor Console记录](console-p2b.json)保留一次QuickInstaller枚举eval动态程序集的已知`ExecutionEngineException`；本轮Player构建成功且两次完整运行日志无该异常。该工具问题不被隐藏，也不计为场景通行失败；后续构建仍遵循先重新加载脚本域、再直接执行原生构建菜单的顺序。
