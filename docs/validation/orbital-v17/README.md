## 灰模到正式资产

`gray/` 保存 Unity 内的真实灰模渲染。检查了主站／实验站／双舱的体量与空间留白、赛场取景、实验站窗外的竞技场，以及裁判的外移位置。灰模检查发现并修复了 FBX 左右坐标翻转，正式资产中的暖色灯和麦克风位于解说舱；减弱玻璃镜面反光并将实验舱向中央收拢。

`blender-gray.json`、`blender.json` 记录各部分网格和三角形数。正式资产共 24 个材质合并网格、40,948 个三角形；实验站与转播设施分别保存为 Prefab，室内部分可独立关闭。旧竞技场的看台保留，场边裁判桌、椅子与阶梯移除。

## 自动实机验收

使用 `--arena-orbital-validation --arena-no-migrate --arena-data-dir <隔离目录> --arena-qa-output <证据目录>`。发行版携带 Node，测试进程 PATH 不包含系统 Node。该流程不依赖网页和外部模型服务。

- 首页和设施中隐藏战斗 HUD；场景标识、两秒过渡、重复点击跳过与 Esc 返回。
- 返回时恢复全场视角、选手聚焦和自由镜头；装饰不增加战斗自动取景目标。
- 实验站窗外竞技场位于视锥内；裁判离开主平台；室内细节仅在访问相应设施时开启。
- 真实比赛后端使用内置 demo 选手完成比赛，验证旅行期间赛事 ID 连续、事件序号推进且未暂停。
- 解说灯以受控的 `working` 文本快照检验显示响应，此项是展示信号测试，不冒称真实云模型或语音发言测试。

每个位置使用 Unity 实际帧间隔采样 10 秒，截图写盘不包含在采样内。结果是本机短时性能记录，不是长时间压力测试。最终构建的 JSON、原始截图与日志保存在 `windows-release04-1080`、`windows-release04-1440`、`windows-release04-2160`；早期 `windows-*` 目录保留为过程记录。

## 原生流程与鼠标检查

`native-regression/desktop.json` 记录 v17 build-02 的原生流程回归：模型管理、连接检测、中文与代码题、暂停、Pi 解说、比赛、历史、排行榜、回放及答题中保存退出通过。模型回答来自 `desktop-ui-fixture.ts` 本地固定响应服务，未调用付费模型；该临时服务已关闭。游戏退出后自带后台停止，测试数据锁释放。v17 没有修改后端；这次未将 v16 的后端单元测试结果冒称为重新执行。

实际鼠标检查发现：首页透明背景挡住设施标识点击，解说面板打开时下层设施控件透出。build-03 修复了事件遮挡和叠字，并新增 UI 射线命中与面板返回检查。该次检查在画面更新前断言而失败，原记录保留在 `windows-release-1080`；build-04 将断言移到帧末后重新验收。主程序行为与 build-03 相同，仅调整验收等待时序。

最终发行版再次用真实鼠标点击首页实验站标识、赛场解说舱标识，进入近景并展开解说面板；首次 Esc 关闭解说面板，第二次返回赛场，再从 Esc 菜单回首页，全部通过。`installed-final/` 保存本次原生窗口截图与日志，发行版已留在首页。没有为了检查而启动用户自己的实验或付费比赛。

## 构建与回退

`build-01.log` 为首轮构建，`build-02.log` 包含镜头接管期间的取景隔离修正，`build-04.log` 为最终发行构建。原工程编辑器独立保留，未重写用户场景。原生入口、后台生命周期与比赛规则沿用 v16。

正式安装后通过项目根目录 `Start-Game.cmd` 启动。旧 v16 程序保留在 `QuQuArena3D/BuildProduction-before-orbital-v17`；正常关闭新游戏后可运行旧版本。两个版本使用同一份既有用户数据，本轮没有数据格式迁移。

安装先校验完整发行目录 12,327 个文件；最后两项界面修复后，重新核对 182 个 Unity 输出文件。`installation.json` 记录安装位置和程序集 SHA-256。Blender 源文件位于 `production/orbital-v17/facilities.blend`，灰模另存为 `facilities-gray.blend`；本轮 Meshy 消耗为 0。
