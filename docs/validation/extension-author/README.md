# Codex 扩展开发验收

## 原生验证

`codex-create.json`、`codex-resume.json`：真实本机 Codex 通过 App Server 与会话 MCP 工具完成 `echo_note` 工具、`note-prefix` 参数、中文及空文本用例。第二轮继续同一个原生会话，调整参数和用例，保留人工添加的 `USER_EDIT_KEEP` 标记。两次检查各 2 个用例全部通过；最终包摘要记录在续改证据中。生成期间未调用参赛模型、未启动 Benchmark、未写入生产配置。

## 自动化和网页

- `regression.log`：387 项现有及新增测试通过，无跳过；包含真实 ExtensionRunner 与 Docker 功能用例、错误扩展负例、会话隔离、版本冲突、取消和重启恢复。
- `final-author-tests.log`：最后 7 项开发专项检查通过，补充确认新草稿默认包名相互独立，可组合而不冲突。
- `browser-checks.json`：9 项完整网页流程通过，浏览器错误为空。网页、Sites 队列、本机执行器、源码持久化和容器测试真实；这组浏览器验收中的 Codex 响应使用脚本化会话，不消耗真实模型额度。
- `visual-checks.json`、`real-author-*.png`：以真实 Codex 产物检查三个桌面视口、固定头部和操作区、乱序快照，以及多扩展回填和升级兼容。
- Sites 独立中继测试 7 项通过，两个项目类型检查通过。

## 修正记录

保留 `ui-failure.png` 及 `author-failure.png` 作为过程证据。前者来自预览认证重定向的初次检查；后者是有意注入的无行为扩展，用于证明功能用例会失败。截图初稿发现编辑器外层发生程序性滚动，已改为固定头尾和独立内容滚动，最终视口验证通过。手工编辑后检查失效、并发保存不覆盖，以及旧快照不回滚新内容均已验证。

这些验证确认工作流和实现行为，不是扩展提分的科学结论。正式效果需要另建开发集/保留集对照实验。
