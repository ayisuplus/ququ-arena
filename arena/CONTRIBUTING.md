# 贡献指南

欢迎投喂蛐蛐罐（benchmark 包）与代码。本项目的第一公民是**题目质量**——一个好罐子比十个大罐子值钱。

## 贡献一个蛐蛐罐

1. 造罐：`node src/cli.ts invent "你的脑洞"` 生成骨架（有 API Key 时由出题官 Agent 出题），然后**手工打磨**——Agent 负责起飞，人类负责降落。
2. 体检：`node src/cli.ts validate <罐名>` 必须 0 错误；警告逐条确认（近重复题、答案泄漏、缺 canary 都会被抓）。
3. 自测：跑一场 mock 赛确认区分度——`node src/cli.ts battle --arena <罐名>`。四只内置蛐蛐战力分层（0.45~0.92），好罐子应该能把它们拉开。
4. 提交：`arenas/<罐名>/` 目录（`arena.json` + `tasks.jsonl`）走 PR。`arena.json` 必须带 `canary`（invent 会自动生成）——这是下游过滤训练语料的标记。

### 题目质量标准

- **区分度优先**：至少有一个"悬崖维度"——当前最强模型也会翻车的子任务。罐里没有团灭题，就没有名场面。
- **可判分**：`exact` 裁判的题必须有唯一标准答案；开放式题必须给 rubric，且 rubric 要具体到裁判间能达成一致（`--judge a,b` 双裁判跑一遍，分歧 ≥3/10 分的题回去改 rubric）。
- **原创**：不写教科书泛题；撞库（训练语料已有的题）等于送分。

## 贡献代码

- `npm test` 必须全绿；新可观测契约补测试（`test/*.test.ts`，node:test 原生）。
- 评分与判定逻辑必须确定性可复现：不许在裁判/统计链路里接 LLM 或引入未固定种子的随机。
- 解说、海报等"放飞"层只消费已算好的数据，不新造数字。

## 提交信息

`罐: <罐名>` / `引擎: <改动>` / `战报: <改动>` 前缀 + 一句话动机。
